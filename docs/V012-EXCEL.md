# V-012 · Excel 붙여넣기, 표 편집, 그래프 인수인계

범위와 참고 화면은 원본 작업 트리의 `docs/VOC.md`와 `docs/voc-assets/V-012-excel-home-ribbon.png`에 있다. V-012는 전체 수용 기준이 충족될 때 완료한다.

## 현재 상태

- 기준 커밋 `d4e4b5d`에서 Excel HTML은 너비 때문에 가려진 텍스트를 버렸다. 가짜 Excel 내보내기 자료에서 `LOT-TEST-001`이 `LOT-TEST-`가 되는 것을 재현했다. 이전 격리 브랜치의 `585e682` 구현과 회귀 검사를 현재 노트 경로에 이식했다.
- Excel로 식별한 HTML의 끝에 붙은 숨김 텍스트를 원래 값으로 복원한다. 일반 HTML의 숨김 요소와 숨김 행은 계속 제외한다. 가짜 Excel 내보내기의 전체 값·12.5% 표시 문자열·셀 내부 개행을 GFM 저장과 재열기에서 확인했다.
- GFM 표는 병합 영역을 펴고, 색을 팔레트로 치환하며, 정렬을 열 단위로 저장한다. 셀 너비·행 높이·테두리·세로 맞춤·회전과 숫자의 원래 값 및 표시 형식을 저장하지 않는다. 확인한 자료는 Excel의 웹 페이지 내보내기이며 Windows의 실제 Ctrl+C/Ctrl+V는 별도 검증이 필요하다.

## 가져오기 파서 구현

- Excel HTML을 표로 분류하면 기존 GFM 변환과 함께 `block.excel`에 원본 범위 데이터를 반환한다. 병합 시작 좌표와 범위, 행 높이, 열 너비, 셀 크기, 색·글꼴·테두리·맞춤·들여쓰기·텍스트 방향의 지원 선언을 담는다. 붙여넣기 한도로 잘린 병합은 반환 범위 안으로 줄이고 병합에 덮인 칸은 별도 셀로 만들지 않는다.
- 숫자의 원시 문자열은 유효한 명시적 `x:num`에서만 구한다. `x:num`의 값이 비어 있거나 원시 값이 없으면 표시 문자열만 유지한다. 원본 CSS의 `mso-number-format` 선언 값은 코드 재해석 없이 보존한다. 따옴표 안의 세미콜론을 보존하여 다구간 표시 형식이 잘리지 않는다.
- 셀 안의 서식이 달라지면 선택적 `richText`에 줄별 텍스트 구간과 해당 구간의 허용된 글꼴·색·장식 속성을 담는다. 별도 Excel 프로세스에서 만든 가짜 웹 페이지에서 일반 굵기로 돌아가는 구간, 16pt Arial 기울임, 원본 글자색, 겹밑줄과 취소선이 함께 있는 구간, 개행을 확인했다. Excel은 겹밑줄을 `text-underline-style:double`로 기록했다.
- 노트 저장은 D-20/D-43의 GFM을 사용한다. 원본 크기·색·겹밑줄 등 메타데이터는 파서 결과에만 있다. 가짜 표의 `=1/8` 수식 셀은 웹 내보내기에서 12.5% 표시와 형식 코드만 제공했다. 실제 클립보드의 수식, 조건부 서식 규칙, 숨겨진 행·열, 지역별 표시 형식 및 보조 클립보드 형식을 후속 확인한다.
- 가짜 Excel 웹 페이지 내보내기에서 열 너비, 행 높이, 병합, 색, 테두리, 12.5% 표시 형식, 가려진 Lot 접미사와 줄바꿈을 파서에서 확인했다. 그 파일에는 해당 숫자의 원시 값이 없었다. Edge에서는 기존 GFM 자동저장과 새로고침을 확인했다. 실제 Windows Ctrl+C/Ctrl+V 검증은 남아 있다.
- Excel 웹 내보내기는 공통 CSS에 `text-align:general`을 쓰고 백분율 셀에 `align=right`를 따로 썼다. 셀 메타데이터에는 이 속성의 방향을 기록하고, CSS에 명시적인 맞춤이 있으면 그 선언을 우선한다. 표의 `numberSeparators`에 Excel의 소수점·천 단위 구분 기호 선언을 이스케이프까지 보존한다. 구분 기호로 빠진 원시 숫자를 추정하지 않는다. 가짜 Excel 내보내기 파일과 소수점 쉼표 합성 사례로 확인했다.
- Windows Excel 웹 내보내기는 숨김 열을 `<col style="display:none">`으로 표시하면서 해당 열의 값은 일반 셀로 내보낸다. Excel 표를 가져올 때 숨김 열의 값은 제외하고 열 너비와 병합 좌표를 보이는 열 기준으로 맞춘다. 병합 영역이 일부 보이면 첫 보이는 칸에 원래 값과 서식을 유지한다. 일반 HTML 표의 기존 동작은 유지한다. 숨김 범위 자체를 복원하거나 다시 표시하는 저장 기능은 후속 표 모델에서 검토한다.
- Excel의 무늬 채우기는 배경색과 `mso-pattern`의 전경색·무늬 이름으로 내보내진다. 파서는 배경색을 셀 서식에, 검증한 무늬와 전경색을 `fillPattern`에 기록한다. 단색으로 내보낸 `none`은 배경색만 기록한다. 가짜 내보내기에서 회색 점과 가는 가로 줄의 전경색을 확인했다.
- Excel은 숨김 행도 `rowspan` 값에 포함한다. 숨김 행을 원본 좌표에 포함해 셀과 병합 위치를 계산한 뒤 결과에서 제외한다. 시작 행이 숨겨진 병합은 첫 보이는 칸에 원래 값과 서식을 둔다. 전부 숨겨진 병합은 출력에서 제외한다. 가짜 내보내기의 두 시작 위치와 함께 격리 Edge의 합성 붙여넣기·GFM 자동저장·새로고침을 검증했다.
- Excel 웹 내보내기의 `mso-ignore:colspan`은 긴 텍스트의 넘침과 연속 빈 칸의 표시용이다. HTML에 선언된 너비만큼 열 위치를 진행하고 원본 셀은 한 열로 기록한다. 표시용 영역은 병합 수에 포함되지 않는다. 가짜 시트에서 실제 병합, 숨김 열과 넘침이 겹친 경우, 왼쪽·가운데·오른쪽 맞춤과 다음 셀 좌표를 검증했다.

## 저장 설계안 · 검토 대기

기존 일반 GFM 표를 그대로 열 수 있게 유지한다. Excel 전용 표에는 버전이 명시된 구조화 블록을 노트 안에 저장하는 방안을 제안한다. 텍스트로 읽을 수 있고 표·그래프·본문을 같은 저장 및 되돌리기 단위로 묶을 수 있다. 기존 전용 블록 처리와 노트 검색·표 추출·내보내기 경로를 먼저 대조한다.

- `excel-table-block.js`의 저장 후보를 검증했다. 줄 맨 앞의 `mi-excel-table` 코드 펜스에 JSON을 둔다. 버전 1 후보는 표 ID, 순서가 있는 열 ID 목록과 행, 셀별 표시 문자열·선택적 표시 형식·원시 값·병합 범위를 담는다. 원시 값은 문자열 형태의 숫자 또는 텍스트로 기록하고 타입이 확인되지 않으면 `null`을 사용한다. 빈 칸과 병합으로 덮인 칸에는 `null`을 쓴다. 행·열 중복 ID, 겹치거나 경계를 벗어난 병합, 잘못된 값 및 미정의 필드를 거부한다. 최대 1,000행·60열·10,000칸과 펜스당 4 Mi UTF-16 코드 단위로 모델 해석을 제한한다.
- 문서 전체에서 조회할 때 같은 ID의 해석 가능한 JSON 블록이 둘이면 버전이나 셀의 유효성에 관계없이 어느 쪽도 선택하지 않는다. 닫힘 구분자가 없거나 JSON을 해석할 수 없으면 편집 대상으로 열지 않는다. 유효한 표 하나를 교체할 때 기존 표 ID를 확인하고 그 블록만 바꾼다. 나머지 블록, 단 경계, 혼용 개행과 문서 끝은 그대로 남는다.
- Node 검사와 격리 Edge에서 GFM·지원 전용 블록·미지원 버전을 한 본문에 둔 채 인접 문단 편집과 다시 열기를 확인했다. 가짜 DB/vault의 페이지와 독립 이슈 메모, 페이지 승격, 연결 이슈와 페이지의 양방향 쓰기, 앱 재시작에서 원문 일치를 확인했다. 후보 블록은 현재 편집기에서 기존 읽기 전용 코드 블록으로 보인다.
- 기존 Excel HTML 파서가 추출한 서식을 후보에 옮기는 변환을 추가했다. 열 너비는 열 ID를 키로, 행 높이는 행과 함께 둔다. 표시 형식·숫자 구분 기호·셀 크기와 서식·무늬 채우기·줄별 글자 구간을 보존한다. 붙여넣기 및 저장에서 같은 서식 값 검사를 쓴다. Windows Excel로 만든 가짜 웹 내보내기 4종과 Node 회귀 자료에서 파서가 추출한 셀·서식 메타데이터 전체를 저장 후 대조했다. 이 변환을 노트 편집기의 붙여넣기·쓰기와 연결하기 전 복사·정렬·차트 참조 규칙 및 검색·내보내기·fill-table 경로를 확정한다.
- 노트·이슈 메모의 블록 편집기, 원문 모드 및 마크다운 미리보기, 검색, 내보내기와 함께 검토한다. 기존 GFM만 읽는 fill-table 스킬에서 Excel 표를 어떻게 찾아 수정할지도 정한다. 기존 편집 경로가 원본 데이터와 표시를 따로 갱신하면 불일치할 수 있으므로 저장 계약에 함께 포함한다.
- 저장 호환성 검증에서 코드 펜스 안의 예시 표가 `fill-table`의 GFM 표 번호를 바꾸던 문제를 수정했다. 펜스의 문자·길이·닫힘 조건을 노트 편집기와 맞추고, 앞 GFM 표가 `|`가 든 펜스 여는 줄을 삼키지 않게 했다. CLI에서 두 번째 GFM 표만 수정하면서 혼용 줄 끝, 파일 끝 개행 유무와 백업 원본을 보존함을 확인했다. 격리 Edge에서 동일한 펜스의 원문과 단 경계 분리를 확인했다.
- 저장 호환성 검증에서 주석 속 예시 표와 제목·인용·목록 줄, 잘못된 파이프 블록도 편집기와 같은 경계로 판별하도록 `fill-table`을 보정했다. 양쪽에서 같은 문서의 편집 가능한 표 두 개를 확인하고, CLI로 두 번째 표만 수정해 백업과 인접 블록의 원문을 대조했다.
- 통합 검색은 페이지 본문과 페이지에 연결된 이슈에 같은 검색 텍스트를 사용하며, 단독 이슈 메모는 tasks.note에서 읽는다. 화면 안의 이슈 목록 검색은 별도 SQL LIKE 경로이므로 저장 블록을 도입할 때 함께 검증한다. 편집용 블록을 도입하면 페이지와 페이지 없는 이슈 메모 모두 검증한 셀 표시 문자열을 검색 대상으로 추출하고, 검색 결과에 구조 메타데이터가 섞이지 않도록 검토한다. 백링크는 기존 코드 펜스 제외 규칙을 유지한다.
- 편집 경로는 `note.js`의 공용 `mountEditor`가 `htmlToMd`의 결과를 자동 저장한다. 페이지 저장은 `PUT /api/pages`의 content, 이슈 상세는 `patchTask`의 note를 사용한다. 독립 이슈의 페이지 승격과 연결 이슈에서의 양방향 저장도 같은 본문의 왕복 검증에 포함한다. 새 블록의 직렬화는 같은 경로에서 처리하는 안을 우선 검토한다. 셀·그래프 편집 뒤에는 해당 블록 원문을 한 번 갱신한 다음 공용 저장을 예약하고, 이슈 메모와 페이지 노트 양쪽에서 왕복 검증한다.
- 현재 버전에서 코드 펜스는 `mdconv.js`가 읽기 전용 블록으로 표시하고, 표 바인딩은 GFM에 적용한다. 새 블록을 쓰기 전에 원문 왕복과 블록 인식, 데이터 유효성 검사, 렌더링을 연결한다. 지원하지 않는 버전이나 손상된 블록은 원문 그대로 보존한다. fill-table의 표 번호는 GFM만 센다. 새 표를 지원할 때 기존 번호로 다른 표를 조용히 수정하지 않도록 안정적 표 ID를 사용하는 별도 진입점을 검토한다.
- 표 ID는 한 노트 본문 범위에서 유일하게 하고, 표 ID 및 행·열 ID를 편집·정렬·서버 재시작에도 유지하는 안을 검토한다. 복사본에는 새 ID를 할당하고 함께 복사한 그래프만 새 표를 참조하도록 한다. 같은 ID가 둘이면 연결을 모호 상태로 표시하고 어느 표도 자동 선택하지 않는다. 병합은 시작 셀과 범위로 저장한다. 셀의 원시 값·형식 코드·Excel 표시 문자열을 분리하고 자료형이 불명확하면 원문을 보존한다. 수치 계산과 차트는 타입이 확인된 값만 사용한다.
- 저장 후보에서 표 복사와 행 순서 변경, 셀 값 편집을 검증했다. 복사본은 새 표·행·열 ID를 사용하며 전체 대상 노트의 코드 블록을 검사해 미지원 버전이 사용하는 표 ID도 피한다. 열 너비 키와 행 높이, 병합 및 서식은 복사본에 보존된다. 행 순서를 바꾸면 세로 병합 전체가 같은 순서로 연속 이동해야 한다. 셀 내용은 행·열 ID로 편집한다. 병합 범위 안에서는 시작 셀을 사용하고, 표시 문자열이 달라진 경우 이전 글자 구간을 제거한다. 셀 전체 서식과 표시 형식은 유지한다. 편집기 연동 시 저장 직전의 전체 노트를 기준으로 ID 충돌을 검사하고 복사본을 같은 편집 작업에서 삽입한다.
- 통합 검색·이슈 목록·CLI 이슈 검색에 같은 Excel 셀 표시 문자열을 사용한다. 가짜 DB/vault에서 따옴표·별표·이모지·퍼센트가 포함된 표시 문자열을 찾고 표 ID·원시 숫자·표시 형식 코드를 제외했다. 연결 이슈는 검색 시 현재 페이지를 직접 읽고 독립 이슈는 저장된 메모를 읽는다. 저장 메모와 페이지 원문을 갱신하지 않는다. 검색은 버전·ID·그리드·병합·셀 값의 구조를 검사하고 렌더링은 JS에서 선택적 서식 값까지 검사한다. 지원하지 않는 버전, 읽을 수 없는 블록과 중복 ID의 후보는 표시 문자열 검색에서 제외한다.
- `fill-table excel-tables`와 `excel-export --table-id`는 검색과 같은 그리드 검사를 사용한다. 값 전송용 JSON은 표·열·행 ID와 순서, 표시 문자열, 타입이 확인된 원시 값, 병합 범위를 유지한다. JSON에는 표시 형식과 스타일을 넣지 않는다. 조회 및 내보내기에서 문서를 그대로 두고, 기존 GFM 번호와 `md --table`의 쓰기 동작을 유지한다. Excel 표에 raw 값을 채우는 쓰기 명령을 연결하려면 형식이 지정된 셀에 들어가는 수치·표시 문자열과 앱 동시 저장을 먼저 검증한다.
- 브라우저 자동저장은 처음 읽은 본문 버전을 보내며, 외부 파일 수정과 같은 서버의 페이지·메모 동시 저장을 감지한다. 409 응답 뒤 초안은 탭에 남으며 복사하고 최신 본문을 열 수 있다. 앱과 `fill-table md --apply`는 같은 vault 파일 잠금 내에서 최신 원문을 다시 비교한 뒤 임시 파일로 교체한다. CLI는 쓰기마다 별도 백업을 남긴다. 임의의 외부 편집기는 이 잠금에 참여하지 않는다. Excel 표 채우기 쓰기를 연결하기 전에 숫자·텍스트 입력과 표시 형식 계약을 확정한다.
- `fill-table excel-fill`에서 표·행·열 ID로 채울 위치를 지정한다. `001`은 텍스트, `12,50%`는 별도 원시 수치 `0.125`, 타입이 불명확한 `1,234`는 `null`을 지정해 각각 보존했다. 꾸민 빈 셀의 표시 형식·색과 병합을 보존한다. 표시 문자열 변경 시 이전 글자 구간을 제거한다. 값 충돌이 있으면 저장을 보류하고, 앱이 잠금 대기 중 먼저 저장하면 백업 전에 CLI 쓰기를 거부한다. CLI는 그리드 검사를 사용하고 브라우저 모델은 선택적 서식 값까지 검사한다. 다음 단계는 Final 시안을 기준으로 노트의 전용 표 읽기·붙여넣기·편집 진입점을 연결하고 실제 Excel 클립보드와 대조하는 것이다.
- HTML에서 사용할 서식을 개별 속성으로 추출하고 검증한다. 테두리·색·크기·정렬은 선언 단위로 적용하며 원본 HTML이나 스타일시트를 저장 또는 렌더링하지 않는다. 원본 글꼴이 설치되어 있지 않거나 선택 범위에 필요한 정보가 없으면 비교 검증에 차이를 남긴다.
- 그래프에서 표 ID와 범위·머리글·계열·축을 참조한다. 산점도는 숫자 X 좌표가 필요하고, 막대/선 그래프는 범주형 X 좌표를 지원하는 안이다. 삽입·삭제·정렬·필터 뒤 참조 및 표시 동작을 명시한다. 표 또는 범위가 사라지면 끊어진 연결을 표시하고 되돌리면 복구한다.
- Final 시안의 색·밀도·키보드 포커스와 D-12 버튼·칩을 따른다. 새 표 도구줄과 그래프 배치는 Final 시안에 없어 구현 전 배치 확인이 필요하다.

## 저장된 표의 화면 표시와 셀 편집

- 공용 노트·이슈 메모 편집기에서 지원 버전의 표를 인라인 그리드로 표시한다. 병합, 행·열·셀 크기, 표시 문자열, 표준 CSS 셀 서식과 셀 안의 글자 구간을 반영한다. 무늬 채우기를 표시하고 Office의 `mso-rotate`는 텍스트에만 적용한다. `layout-flow:vertical-ideographic`는 세로로 쌓되 글자를 똑바로 표시한다. 일반 `writing-mode` 표시는 기존과 같다.
- 별도 Excel 인스턴스로 만든 가짜 HTML에서 -90°, -45°, 0°, 45°, 90°와 세로 쓰기를 추출했다. 노트 및 독립 이슈 메모에 붙여넣고 Edge에서 렌더링, 저장·재열기 및 셀 편집을 확인했다. Excel과 브라우저의 좁은 셀 줄바꿈·잘림·자동 맞춤 일치는 남은 시각 검증이다.
- 표 ID의 범위는 단 전체를 합친 본문이다. 다른 단의 미지원 버전이 같은 ID를 사용해도 양쪽을 코드 블록으로 표시한다. 유효하지 않은 블록은 표로 해석하지 않는다. 격리 Edge에서 가짜 노트·독립 이슈 메모의 표시, 인접 문단 자동저장 및 새로고침을 확인했다.
- 저장된 `fillPattern`은 셀 배경색 위에 CSS 무늬로 표시한다. 허용된 17종의 점 밀도·선 방향·교차 무늬를 별도로 표현하며 브라우저에서 원본 펜스의 왕복을 확인했다. Excel과 같은 픽셀 단위 패턴 및 배율은 별도 대조가 필요하다. [Microsoft Excel 무늬 정의](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-xls/10767248-ab46-4581-ae08-310ffcbf026b)
- 방향키로 셀을 선택하고 F2, Enter 또는 더블클릭으로 표시 값을 연다. Enter 또는 포커스 이동으로 확정하고 Esc로 취소하며 Alt+Enter로 줄을 나눈다. 편집과 되돌리기는 단 전체의 ID 유일성을 재확인한다. 병합은 시작 셀만 수정한다. 표시 값 변경 시 기존 원시 값은 미확인(null)이 되며 숫자 형식, 병합과 셀 서식은 보존된다. 표시가 바뀐 경우에만 이전 글자 구간을 제거한다. Ctrl+Z/Y는 표의 이전·다음 원문을 복원한다. 실제 값 타입을 지정하는 작업에는 현재 fill-table의 명시 입력을 사용한다.

## 노트 본문에 Excel 범위 붙여넣기

- 노트와 독립 이슈 메모 본문에 들어온 Excel 표 HTML은 한 셀부터 범위까지 버전형 표로 붙인다. 병합, 크기, 셀 서식, 표시 문자열과 확인된 원시 값을 함께 저장한다. 원시 값이 클립보드 HTML에 없으면 추정하지 않는다. 새 표 ID는 다른 단의 미지원 블록까지 포함해 이미 사용 중인 ID를 피한다.
- 붙여넣기 옵션의 원본 서식과 일반 텍스트 표를 오갈 때 같은 표 ID로 돌아온다. 이후 셀 편집이 저장되면 이전 붙여넣기 옵션으로 표를 덮어쓸 수 없다. 전용 블록을 만들 수 없을 때는 일반 표로 붙이고 안내한다. 일반 HTML·TSV와 기존 GFM 표의 셀 붙여넣기는 기존 경로를 쓴다.
- Excel에서 생성한 가짜 웹 내보내기 HTML과 원시 숫자가 명시된 1셀 합성 HTML을 격리 Edge에 보내 본문 붙여넣기와 저장을 확인했다. 실제 Excel Ctrl+C/Ctrl+V는 남아 있다.

## 기존 Excel 표에 범위 붙여넣기

- 선택한 셀을 왼쪽 위 기준으로 삼아 Excel HTML 범위를 덮어쓴다. 원본 셀의 표시 문자열·확인된 원시 값·서식·병합을 가져오고, 대상 표·행·열 ID 및 행 높이·열 너비 설정을 유지한다. 범위 전체가 포함하는 기존 병합은 원본 범위의 병합으로 교체한다.
- 범위가 표를 벗어나거나 기존 병합을 일부만 덮거나 복사 영역이 변환 한도로 잘리면 전부 거부한다. Ctrl+Z/Y로 범위 전체를 한 단계에서 되돌리거나 다시 적용한다. 단일 일반 텍스트는 F2로 연 셀 입력란에서 붙일 수 있다.
- 격리 Edge의 노트와 독립 이슈 메모에서 합성 Excel HTML을 사용해 병합 교체·거부, 대상 ID·크기 설정, 원시 숫자와 표시 문자열, 한 단계 되돌리기·다시 적용, 자동저장·다시 열기를 확인했다.

- 붙인 직후 기존 옵션 바의 **값만**을 고르면 원본의 표시 문자열과 확인된 원시 값을 적용한다. 대상 셀 서식·숫자 서식 코드·병합은 유지한다. 표시 문자열을 보관하므로 대상의 숫자 서식 코드로 다시 계산하지 않는다. 문자열이 바뀐 경우 이전 문자열에 연결된 글자 구간은 비운다. 대상 병합에 데이터가 가려질 범위는 안내를 표시한다.
- 원본 서식과 값만 전환은 하나의 작업으로 Ctrl+Z/Y를 적용한다. 후속 편집 뒤 이전 옵션 바의 버튼은 해당 편집을 덮어쓰지 않는다. 노트와 독립 이슈 메모에서 각 모드, 자동저장·새로고침과 되돌리기를 확인했다.

- Excel HTML이 없는 클립보드의 직사각형 TSV 범위도 선택 셀부터 값만 채운다. 따옴표로 둘러싼 탭·개행을 셀 안에 보존하고, 표시 문자열만 사용하며 숫자 타입을 추정하지 않는다. 빈 칸은 기존 표시 값을 비운다. 행별 열 수가 다르거나 경계·병합·변환 한도를 넘으면 범위 전체를 거절한다. 기존 본문과 GFM 표의 붙여넣기 규칙도 확인했다.

## 기존 Excel 셀 내용 지우기

- 노트와 독립 이슈 메모에서 클릭 또는 방향키로 셀을 선택하고 Delete를 누르면 표시 문자열과 원시 값, 해당 문자열의 글자 구간이 지워진다. 병합 셀은 시작 셀에 적용한다. 셀 서식·숫자 표시 형식·병합·크기·표와 행·열 ID를 보존한다.
- 빈 셀에서 Delete를 반복해도 실행 취소 단계가 늘지 않는다. 기존 Ctrl+Z/Y로 이전 값과 글자 구간을 복원하거나 다시 지운다. 차트 모델에서 지워진 원시 값은 빈 값으로 조회된다. 여러 셀을 한 번에 지우는 범위 선택과 리본의 지우기 하위 메뉴는 남았다.
- 격리 Edge의 노트와 독립 이슈 메모에서 실제 클릭·키 입력으로 퍼센트 셀과 글자 구간이 있는 병합 셀을 검증했다. 실행 취소·다시 실행·반복 Delete, 저장된 원문 및 새로고침을 확인했다.

## 표 연결 차트 정의 · 저장 후보

- 같은 노트 또는 독립 이슈 메모 본문 안의 표 ID, 선택한 행 ID 목록, X·Y 열 ID, 선택적 머리글 행 ID를 연결한다. 측정값 복사본 없이 `mi-excel-chart` 버전 1 코드 펜스에 차트 유형과 참조만 저장한다. 모델에서 막대·선의 X는 표시 문자열, 산점도의 X와 모든 차트의 Y는 타입이 확인된 원시 숫자를 사용한다. 0은 실제 값이다. 표시 문자열에만 있는 수치와 병합에 가려진 칸은 빈 값이며 산점도에서 X가 비면 그 행을 그리지 않는다.
- 조회 시 표의 현재 행 순서로 읽고 지정된 Y 열 순서는 유지한다. 새 행은 현재 선택에 자동으로 추가되지 않는다. 선택된 행·열·머리글을 삭제하면 연결이 끊기고 같은 ID를 복원하면 돌아온다. 표가 사라지거나 지원하지 않는 버전이거나 ID가 중복된 경우 데이터 사용을 보류한다. 차트 정의 ID도 본문 전체에서 유일해야 한다.
- Node에서 정렬·셀 수정·병합·참조 삭제 및 복원·중복·미지원 버전·마크다운 왕복을 확인했다. 가짜 vault와 DB의 페이지 저장 API를 별도 프로세스에서 다시 열어 펜스 바이트 보존과 변경된 원시 값으로 재조회되는 것을 확인했다.
- 차트 ID를 유지한 채 유형과 원본 참조를 교체할 수 있다. 다른 단의 중복 ID, 미지원 버전, 닫히지 않은 펜스를 거부하고 다른 차트·표·메모와 혼용 줄 끝을 보존한다. 격리 Edge에서 차트 종류를 교체하고 페이지 API로 저장한 후, 노트 셀을 편집해도 새 정의가 유지되는 것을 확인했다. 별도 앱 프로세스에서 새 정의와 바뀐 원시 값의 재조회를 확인했다.
- 차트 생성·편집·렌더링 UI는 남았다. 표 필터와 함께 쓸 때 표시 범위를 어떻게 처리할지, 차트를 동반 복사할 때 ID를 어떻게 다시 매길지, 새 홈 리본과 차트 배치 및 추가 기능 호환 범위를 연결 전에 확인한다.

| 글꼴 | 글꼴·크기 및 크기 증감, 굵게·기울임·밑줄/이중 밑줄, 테두리의 위치·선색·선종, 채우기·글자색, 캡처에서 보이는 글꼴 관련 추가 명령의 목록 확인. 셀 전체와 셀 내부 텍스트 선택을 구분한다. |

| 표시 형식 | 일반·숫자·통화·회계·날짜·시간·백분율·분수·지수·텍스트 및 사용자 지정 형식, 통화 기호와 천 단위 구분, 소수 자릿수 증감. 한국어 설정과 Excel 날짜 체계로 표시를 비교한다. |
| 스타일 | 조건부 서식 규칙(강조, 상·하위, 데이터 막대·색조·아이콘, 사용자 지정, 규칙 관리), 표 서식(머리글과 줄무늬 등), 셀 스타일. 사용 중인 규칙과 붙여넣을 때 표시된 결과를 실제 복사로 대조한다. |

| 편집 | 자동 합계와 평균·개수·최대·최소, 상하좌우 채우기와 계열, 내용/서식 지우기, 오름·내림차순 및 사용자 지정 정렬과 필터, 찾기·바꾸기·이동·조건 선택. 수식 표현 범위와 오류 표시 기준을 정한다. |
| 추가 기능 | 오프라인 MI_Planner 기능 실행이 요구인지 Excel 추가 기능과의 호환까지 포함하는지 확인한다. |

실제 Excel에서 각 하위 메뉴를 펼쳐 목록을 대조한다. 가짜 표의 서식과 병합을 나란히 비교한 뒤 편집, 되돌리기·다시 실행, 그래프 생성과 원본 표 수정, 저장·새로고침·서버 재시작으로 검증한다. 표 편집기 격리 시험에는 가짜 DB/vault와 별도 Edge 프로필을 사용한다.
