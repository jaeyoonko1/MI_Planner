# VOC — 사용자 의견·불편·요청함

> 사용자가 말한 의견을 **VOC 관리 담당**이 정리해 기록한다. **작업을 고를 때 flow보다 먼저 본다** (AGENTS.md 2·6장).
> 처리가 끝나면 `상태`를 `완료`로 바꾸고 커밋 해시를 적는다. 지우지 않는다. 같은 내용이 `project_flow.html`의 "VOC" 단계에도 있으니 둘을 함께 갱신한다.

## 쓰는 법
- 한 건 = 한 줄. ID는 `V-001`부터 순서대로, 한 건 = 한 세션, 커밋 메시지는 `[V-001] 설명`.
- **우선순위 1~5** — **1이 가장 급함**(쓰기 막힘·데이터 위험·핵심 흐름), 5가 가장 여유. 사용자가 직접 준 번호가 원본이며 `추정`은 사용자가 정하지 않아 정리 담당이 매긴 것.
- **분류**: `버그`(있어야 할 동작이 안 됨) · `개선`(있는 기능을 더 낫게) · `기능추가`(없던 기능)
- 상태: `대기` · `진행` · `완료` · `보류`(사유 기재)

## 항목 상세
### V-011 · Jira식 이슈 계층으로 전환: 구조에서 모든 수준의 이슈 직접 추가·수정·삭제
- 분류: **개선**(추가·삭제 동작 누락 포함) · 우선순위: **1 (추정)** — 사용자가 현재 구조를 Jira처럼 활용할 수 없어 핵심 애자일 업무 흐름이 막힌다고 보고함. · 영역: 업무 구조·이슈 계층·분류 관리·이슈 상세 · 예상 크기: **L** · 상태: **완료** (커밋은 아래 완료 표, 결정 D-48).
- **목적**: 애자일 방식으로 일할 수 있도록 업무 구조의 이슈 생성·계층·편집 경험을 Jira에 최대한 가깝게 개선한다. 아래 요구는 분리 VOC를 만들지 않고 **한 건(V-011)**으로 처리한다.
- **사용자 보고**: 현재는 구조에서 원하는 상위 항목을 바로 만들기 어렵고 분류 관리에 값을 하나씩 등록해야 한다. 분류 삭제도 되지 않는다. 삭제 불가의 실제 원인과 범위는 구현 착수 시 확인한다.
- **핵심 요구**:
  1. 업무 구조에서 이슈를 바로 추가한다. 에픽·유형·그 외 사용자 정의 수준 모두 이슈 단위로 취급하여, 특정 계층만 별도 분류 값으로 만들어야 하는 흐름을 없앤다.
  2. 예를 들어 `프로젝트`, `스터디`, `업무`, `결혼준비`를 에픽 수준의 항목으로 만들고 싶으면 분류 관리 화면을 거치지 않고 구조 화면에서 직접 추가할 수 있다. 이 이름들을 고정된 기본 분류로 강제하지 않는다.
  3. 구조의 에픽·유형 등 모든 수준의 항목을 수정·삭제할 수 있어야 한다. 기존 분류 삭제 불가 문제도 같은 VOC 범위에서 조사·해결한다. 기존 휴지통·되돌리기 원칙을 지키며, 하위 이슈가 있는 항목의 삭제·이동 처리를 설계하여 데이터 유실을 막는다.
  4. 이슈의 에픽/상위 소속을 `프로젝트` 등으로 변경하면 구조의 해당 헤더 아래로 바로 반영되어야 한다. 이슈 상세의 값과 구조의 부모·자식 관계가 일치해야 한다.
  5. 헤더를 `에픽 헤더`로 할지 `유형 헤더`로 할지는 미정이며, 사용자는 후자 쪽을 선호한다. **`유형`이라는 용어 자체도 임시**이므로 확정 명칭이나 고정 계층으로 간주하지 않는다. 이슈의 종류·계층 수준과 이슈 제목/상위 소속의 구분은 설계에서 명확히 한다.
- **수용 기준**: 구조에서 위 예시의 상위 이슈와 하위 이슈 생성 → 이슈 종류/수준·상위 소속 수정 → 헤더·계층 즉시 반영 → 각 수준 삭제 및 되돌리기 → 새로고침/재시작 후 관계 유지까지 하나의 흐름으로 검증한다. 기존 이슈·분류·일지 연결은 보존하거나 명시적인 이관 방안을 마련한다.
- **설계 시 확인**: Jira에 가깝게 만드는 구체적인 동작과 헤더 명칭은 이 요구를 기준으로 정리한다. 보드·스프린트 등 사용자가 이번에 구체적으로 요청하지 않은 기능의 추가를 자동으로 확정하지 않는다.
- **처리 결과 (2026-11-24, D-48)**: 상위 수준도 `tasks` 행(이슈)이고 계층은 `parent_task_id`. 수준(에픽 등)은 `issue_levels`(마이그레이션 013)로 정의하며 이름·모양·색·순서를 구조의 '계층 편집'에서 바꾼다. 구조의 기본 보기 = **이슈 계층**(분류 기준·자유 배치는 그대로 선택 가능). **헤더 명칭**: 고정 문자열을 두지 않고 헤더 행 = 이슈 제목 + 수준 배지로 표시, 기본 수준 이름은 `에픽`(이슈 상세의 기존 분류 `유형`과 같은 이름이 둘 생기지 않게). 계층 편집에서 `유형`으로 바꾸면 그대로 반영(마이그레이션 불필요). **분류 삭제 불가 원인**: 서버 삭제 API는 정상. 구조 화면이 분류 기준 그룹 행의 삭제를 막고('분류 관리에서 정리') 분류 관리는 쓰는 값이 있으면 '보관'만 해서 사용자는 지울 수 없다고 느낌 → 분류 기준 보기의 그룹 행(분류 값)을 Delete/F2로 바로 삭제·이름 변경(값만 지우기/이슈도 삭제, Ctrl+Z 복원). 기존 분류 값은 그대로 두고, '분류 값을 상위 이슈로 가져오기'로 명시적으로 이관한다.
