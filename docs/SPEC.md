## 1. 목표

### 해결하려는 문제
- 검사 대기·Review 대기 현황이 사내 시스템, 메모, 머릿속에 흩어져 있어 **"지금 뭐가 제일 오래 기다리고 있나"**를 바로 알기 어렵다.
- 원노트는 표가 약하고, 옵시디언은 회사 PC에서 고치기 어려웠고, Jira는 개인 할일·Lot 단위 관리에 무겁다.
- 기존의 원노트의 계층 구조식 노트 (컨플루언스와 유사) 가 굉장히 마음에 들었었다. 옵시디언을 도입해보려 했으나, 폴더 내 노트가 위치하는 방식이다 보니 폴더에 노트를 추가 못하는게 굉장히 아쉬웠다
- 원노트의 가장 큰 이점은 더블클릭으로 접기 가능, 표 마음대로 놓기 가능, 텍스트를 원하는 위치에 바로바로 쓸수 있어서 옵시디언과 같이 수직으로 쭉 내려오는게 아닌 수평으로 배치도 가능했다. 하지만 아무렇게나 배치가 되다보니 정리가 어려운 문제점이 있었다.
- 예를들어 월단위 일지를 한 노트에, 주마다 1열씩 해서 행이 요일이 되도록 해서 한눈에 한달동안한일이 정리됐다.
- 이를 api 로 사내 llm 모델과 엮어서 하고 싶었지만 one note 호환성이 구려 어려웠다. 
- 원노트는 너무 커지면 따로 백업을 해두고 또 다른 파일에서 처음부터 가능하다. 
- 기존 원노트 구조는 일지 / MI 공정업무 / 연구 개발 / 업무 메뉴얼 / 스터디 이런식으로 되어있다. 
1) 일지 월별 노트/ 주간 열 / 일 행으로 해야할일들 아침에 쭉 쓰고 
   - 여기서 문제는 지라처럼 에픽/스토리로 관리하거나 우선순위를 쓰거나 요청자난 납기등이 없어서 한눈에 안들어와서 놓치는 경우도 많았다.
   - 이번에 한 설비사 3사별 평가 같은 경우엔 랏별로 검사/리뷰/반복도 데이터 확인/scan time 계산/ 디펙 분류 / 디펙 모수 정리 / 이슈 확인 등 챙길게 엄청 많은데 이게 한달에 거쳐 하는 일이다 보니 일지에서만 관리가 사실상 불가능함. 링크를 mi 공정업무로 엮어서 지라처럼 관리했어야함

### 성공 기준
1. 아침에 앱을 열면 **10초 안에** 이번 달 일지(오늘 칸), 오늘·납기 임박 할일, 진행 중 평가의 밀린 단계가 보인다.
2. 새 설비 평가를 시작할 때 **설비·Lot·웨이퍼 목록 붙여넣기 + 템플릿 선택만으로** 현황판이 생긴다 (대시보드를 새로 만들지 않는다).
3. 노트는 원노트처럼 **계층 + 수평 배치(단)** 가 되지만, 단 구조 덕에 정리가 무너지지 않는다.
4. 사내 LLM 에이전트가 **앱 없이도** 노트·일지·평가 데이터를 읽고 채울 수 있다.
5. 인터넷이 끊긴 회사 PC에서 `run.bat` 하나로 돌아간다.

## 3. 핵심 개념

```
워크스페이스(vault/) ─ 페이지 트리
  └─ 페이지 = 폴더 1개 (하위 페이지 = 하위 폴더)
       종류: note(.md) | html(interactive) | journal(월간 일지) | board(평가 현황판) | table(정보 표)

SQLite (data/mi_planner.db) ─ 정형 데이터
  Task ── 페이지·평가에 연결 가능
  Evaluation ──< Equipment, Lot ──< Wafer
       └──< Cell (설비×웨이퍼) ──< StageLog (단계 전환 이력 → 대기 시간)
  EvalTemplate (단계 목록 + 값 항목) ── 평가 생성 시 복사
  LotStatus (MOS 붙여넣기 / 나중에 dcoll)
  Plan, Step, DOI (MI 정보)   Recipe, RecipeParam, RecipeSnapshot (RCP 관리)
```

- **페이지(Page)**: 트리의 한 노드. 폴더이면서 동시에 노트다 → 옵시디언의 "폴더에 노트를 못 단다" 문제를 없앤다.
- **원노트 구조 매핑** (초기 트리, D-24 확정): `일지/`, `MI 공정업무/`(RCP 개발, RCP 관리, 설비사 평가, 각종 정보, DOI List), `연구 개발/`, `성과/`, `업무 매뉴얼/`, `스터디/`. 이 트리가 앱의 **주 내비게이션**이다 — 오늘·할일·월간 일지는 트리 위에 얹힌 보기이지 트리를 대신하지 않는다.
- **사용자 정의 항목(Field)**: 할일에 붙는 속성(요청자·제품·우선순위 등)의 정의. 고정 컬럼이 아니라 사용자가 언제든 추가·이름 변경·삭제한다 (4.2.2, D-22).
- **평가(Evaluation)**: 설비사 평가 1건. 페이지(board 타입)와 1:1. 페이지 본문엔 목적·검증 방식 같은 서술, 현황판은 DB.
- **단계(Stage)**: 평가 칸이 거쳐 가는 상태. 평가마다 편집 가능. 단계에 머문 시간 = 대기 시간.

## 4. 기능 상세

### 4.1 페이지 트리 · 노트 (P1, P3)

**저장 형식 (D-08)**
```
vault/
├─ 일지/
│  ├─ _page.json            {"type":"note","title":"일지","order":0}
│  ├─ index.md
│  └─ 2026-11/
│     ├─ _page.json         {"type":"journal","title":"2026년 11월"}
│     └─ index.md
├─ MI 공정업무/설비사 평가/2026 3사 평가/
│  ├─ _page.json            {"type":"board","eval_id":3}
│  └─ index.md              ← 목적·Lot·검증 방식·평가 항목 서술
└─ 스터디/광학/
   ├─ _page.json            {"type":"html"}
   └─ index.html            ← interactive 강의
```
- `_page.json`: type, title, order, icon(선택), created/updated. 폴더 이름은 사람이 읽을 수 있게(제목 기반), 이동·이름 변경은 앱이 폴더째 옮긴다.
- 첨부파일(이미지·엑셀)은 같은 폴더의 `files/`에.

**노트 편집 (note 타입)**
- 페이지 본문 GET/PUT은 원문의 줄 끝(LF/CRLF/혼용)을 보존한다. 편집기는 바뀌지 않은 마크다운 줄과 읽기 전용 블록을 저장할 때 원문으로 내보낸다.
- 마크다운 기반. 단 경계는 최상위의 독립된 `<!-- column -->` 한 줄로 저장한다. 펜스나 인용의 내부 예시는 경계로 보지 않는다. 기본 블록(P3-01·02 확정): 문단, `#`~`###` 제목, `-`/`1.` 목록, `- [ ]`/`- [x]` 체크리스트, `![](files/이름.png)` 이미지, 인라인 `**굵게** *기울임* ~~취소~~ `코드``. 편집기 결정은 D-20. API 추가: `POST /api/pages/files?path=&name=`(본문=이미지 바이트, 페이지 `files/`에 저장하고 `{file}` 반환, png/jpg/gif/webp/bmp·20MB), `GET /api/pages/file?path=&name=`.
  ```markdown
  왼쪽 내용

  <!-- column -->

  오른쪽 내용 (표 포함 가능)
  ```
- `PUT /api/pages/layout?path=` (note 전용)으로 `{"mode":"fit"|"scroll","widths":[30,70]}`을 저장한다. `widths`를 쓰면 양의 정수 비율 2~4개, 합계 100이다. 이 값을 생략하면 균등 너비가 기본값이다. 페이지 조회의 `meta.note_layout`에 보관하며 본문은 별도로 저장한다.
- **행(V-008)**: `<!-- row -->`(최상위 독립 한 줄, 단 경계와 같은 규칙)은 그 아래에 새 **단 행**을 시작한다. 행마다 단은 1~4개, 행은 최대 6개이며 한도를 넘는 표식은 그냥 본문으로 남는다. `<!-- column -->`은 같은 행의 다음 단이다. 표식이 없는 파일은 한 줄도 바뀌지 않는다. 예: 두 단 + 아래 한 단 = `왼쪽 <!-- column --> 오른쪽 <!-- row --> 아래`.
- 행이 둘 이상이면 레이아웃은 `{"mode":"fit","rows":[[40,60],[100]]}`(행마다 1~4개, 합계 100)로 저장한다. 한 행뿐이면 이전과 같은 `widths`(2~4개) 또는 `mode`만 쓴다. `rows`는 2~6행일 때만 허용되고 `widths`와 함께 보내도 된다.
- **단·행 편집(V-008)**: 단마다 마우스를 올리거나 키보드로 들어가면 작은 도구줄(왼쪽에 단 추가 / 오른쪽에 단 추가 / 아래에 행 추가 / 삭제). 단축키 `Alt+Shift+←·→`(단 추가), `Alt+Shift+↓`(행 추가), `Alt+Shift+Delete`(단 삭제)는 "단 단축키" 버튼에 표시된다. 삭제는 내용이 있으면 확인 패널의 토글 칩으로 **앞(뒤) 단에 합치기** / **내용까지 삭제**를 고르고, 빈 단은 바로 지운다. 단이 행의 유일한 단이면 행 전체가 사라진다. 마지막 남은 단은 지울 수 없다. 모든 변경은 세션 안에서 토스트의 되돌리기 버튼과 Ctrl+Z로 되돌린다(그 뒤에 입력하면 편집기 자체 실행 취소로 돌아간다). 삭제된 내용은 페이지 저장 외에 파일을 지우지 않는다(이미지 파일도 폴더에 남음).
- **단 추가**(2~4단), 경계 드래그로 **열 너비 조절**(비율 저장).
- 페이지별 표시 모드 버튼: **스크롤**(단이 고정 너비, 가로 스크롤) / **맞춤**(화면 너비에 맞춰 축소).
- 제목 **더블클릭으로 접기**(접힘 상태는 보기 설정으로 저장, 파일 내용은 안 바꿈).
- **서식 (D-15)**: 글자 크기, **굵게**, *기울임*, 밑줄, ~~취소선~~, 형광펜(배경색), 글자색. 위지윅 편집(보이는 그대로 편집) + 툴바 + 원노트와 같은 단축키(Ctrl+B/I/U, Ctrl+Alt+H 형광펜 등).
  - 저장 형식: 마크다운 + **허용된 인라인 HTML만** — `<u>`, `<mark style="background:…">`, `<span style="color:…; font-size:…">`. 그 외 태그·스타일은 저장 시 제거.
  - 크기·색은 프리셋(크기 6단계, 색 10개 정도)으로 제한 → 파일이 지저분해지지 않고 LLM도 읽기 쉽다.
  - P3-01 spike에서 "편집 → 저장 → 다시 열기" 왕복 시 서식이 유지되는지 먼저 검증. 실패하면 대안: note 본문을 정제된 HTML로 저장.
- **표 블록**: 노트 또는 이슈 메모에서 `표 추가`를 누르거나 기존 GFM 표의 셀을 바로 편집한다. 열 머리글 버튼은 본문 행만 오름차순·내림차순으로 정렬하며 그 순서를 마크다운에 저장한다. `Shift+클릭`으로 사각 영역을 선택하고 `선택 복사` 또는 `Ctrl+C`로 엑셀용 TSV를 복사한다. 붙여넣기는 활성 셀부터 적용하며 필요한 행과 열을 추가한다. 셀은 마크다운 원문으로 편집하고, 붙여넣은 값의 파이프와 줄바꿈을 이스케이프하여 같은 GFM 표에 저장한다. 편집하지 않은 표와 인접 블록은 원문을 보존한다.
- 페이지 링크 [[페이지 제목]] + 백링크, 전체 텍스트 검색 (P3-08). 고유 제목으로 연결하고 동명일 때는 [[폴더/페이지]]를 쓴다. [[를 입력하면 페이지와 경로를 제안한다. 링크를 열 때는 Ctrl+클릭 또는 링크 안에서 Alt+Enter를 쓴다. 코드·주석·이스케이프한 링크는 백링크에서 제외하며 페이지 이름이나 위치를 바꿔도 기존 본문을 일괄 재작성하지 않는다.
- / 또는 Ctrl+K로 검색 팔레트를 열어 페이지 제목·본문, 이슈 제목·메모와 앱 명령을 찾는다. GET /api/search?q=&limit=는 {pages:[{title,path,type,snippet}], tasks:[{id,title,path,snippet}]}을 돌려준다 (기본 그룹당 30개). GET /api/search/backlinks?path=는 {pages:[{title,path}]}를 돌려준다. 검색은 현재 vault와 DB를 읽으며 검색용 별도 파일을 만들지 않는다.

**HTML 페이지 (html 타입)**
- `index.html`을 앱 안 iframe(sandbox)으로 표시. 강의·로드맵·계산기 등.
- 오프라인 규칙: 외부 CDN을 쓰는 HTML은 경고 표시 (LLM 스킬에도 같은 규칙).
- 상태 저장이 필요한 HTML(체크리스트 등)은 앱이 제공하는 작은 저장 API를 쓴다 (P3-07 확정).
  - `GET/PUT /api/pages/state?path=` — 페이지 폴더의 `_state.json`(JSON 객체, 최대 1MB). html 타입만 허용.
  - `GET /api/pages/external-refs?path=` — index.html의 외부 URL(src/href/url()/@import/fetch 등) 목록 → 프론트가 경고 배지 표시.
  - 표시: `<iframe sandbox="allow-scripts">`(same-origin 없음) + srcdoc에 CSP(`connect-src 'none'` 등)를 주입해 외부 요청을 차단. iframe 안에서는 `parent.postMessage({miPlanner:"state-get"|"state-set", id, state}, "*")`로 요청하고 `{miPlanner:"reply", id, state|error}` 응답을 받는다.

### 4.2 월간 일지 · 할일 (P2)

**월간 일지 (journal 타입)**
- 화면: **열 = 주(週), 행 = 요일**(월~금, 주말 접기). 오늘 칸 강조.
- 칸 = 그날의 자유 텍스트(노트와 같은 서식 편집기, 체크박스 줄 가능).
- 파일 형식: 날짜 제목 아래 내용 — LLM이 그대로 읽고 쓸 수 있다.
  ```
  ## 2026-11-24
  - [ ] 3사 평가 Lot2 리뷰 요청
  - 설비 A 레시피 문의 회신
  ```
- **자동 표시 (옵션, D-13)**: 켜면 칸에 그날 납기인 할일, 진행 중 평가의 밀린 단계 요약을 읽기 전용으로 함께 보여준다. 파일에는 쓰지 않는다.
- 체크박스 줄 → **할일로 승격** 버튼 (원래 줄에 할일 링크 남김).
- 월이 바뀌면 새 월 페이지 자동 생성. 연 단위로 `일지/2026/`처럼 묶어 보관(원노트식 "파일 분리" 대체).
- **확정(P2-01)**: 월 페이지 경로는 `일지/<yyyy>/<yyyy-mm>` (폴더명 고정, 표시 제목은 "2026년 11월"). 날짜가 아닌 `##` 제목과 코드펜스 안의 내용은 본문으로 취급. 내용이 빈 날은 섹션을 지운다. 섹션은 저장 시 날짜순으로 정렬.
- API 응답: `GET /api/journal/{yyyy-mm}` → `{month, path, days: {"YYYY-MM-DD": 본문}}` (없는 월 페이지는 이때 자동 생성). `PUT /api/journal/{yyyy-mm}/{dd}` body `{content}` → 같은 형태.

### 4.2.1 줄 편집 — 원노트식 빠른 입력 (D-21, 신규)

- **Tab / Shift+Tab의 경계 (버그 보고 2026-11-24 반영)**: 여러 줄 본문(오늘 기록·날짜 일지·할일 메모·할일 페이지·노트)을 편집 중이면 Tab은 현재 줄 또는 선택한 모든 줄을 한 단계 들여쓰고 Shift+Tab은 한 단계 내어쓴다. **편집기 안에서는 웹 단축키 설정과 관계없이 항상** 이렇게 동작하고 포커스가 다음 요소로 넘어가면 안 된다(사용자 보고: "탭을 누르면 아예 넘어간다"). 편집기를 키보드로 빠져나갈 때는 `Esc` 후 `Tab`. 본문 밖에서는 기본 포커스 이동. 한 단계는 공백 두 칸, 들여쓰기는 바로 윗줄보다 한 단계 넘게 깊어지지 않는다.
- 제목이나 들여쓴 부모 줄의 접기 상태는 본문과 분리한다. 더블클릭으로 자식 범위를 접었다가 다시 펼쳐도 내용은 보존한다.
- 붙여넣은 이미지는 원본 비율을 유지해 본문 너비 안에 표시한다. 호버 또는 키보드 포커스로 자동 너비, 소형, 명시적 픽셀 너비를 선택한다.
> 사용자의 실제 습관: 아침에 오늘 할 일을 일지 칸에 **불렛으로 쭉 쓰고, 탭으로 구조화하고, Ctrl+1로 표시를 바꿔가며** 관리한다. 이 흐름이 앱의 1순위 입력 경로이고, 할일 화면·승격은 그 위에 얹힌다. **마우스 없이 키보드만으로 끝나야 한다.**

| 동작 | 키 | 비고 |
|---|---|---|
| 불렛 줄 켜기/끄기 | `Ctrl+.` | 줄 앞에 `- ` |
| 한 단계 들여쓰기 / 내어쓰기 | `Tab` / `Shift+Tab` | 2칸 단위. 여러 줄 선택 시 일괄. 하위 불렛 = 구조화 |
| **줄 표시 순환** | `Ctrl+1` | `없음 → ☐ → ☑ → ★ → ! → 없음` 순으로 한 번에 한 칸 (**순서 `[가정]`**). 불렛 없는 줄이면 불렛을 먼저 붙인다 |
| 줄 이동 | `Alt+↑/↓` | 하위 줄 포함 `[가정]` |
| Enter | | 현재 줄의 불렛·들여쓰기 유지, 빈 불렛에서 Enter = 내어쓰기/불렛 해제. 표시(☐ 등)는 이어받지 않고 빈 불렛 |

- **저장 형식**(사람·LLM이 그대로 읽음, 기존 `- [ ]` 호환):
  ```
  - [ ] 3사 평가 Lot2 리뷰 요청        ☐ 할일
    - [x] 데이터 수집                   ☑ 완료
    - [*] 반복성 그래프 정리            ★ 중요
  - [!] 장비 알람 원인 확인             ! 긴급
  - 설비 A 레시피 문의 회신             표시 없는 불렛
  ```
  `[*]`·`[!]`는 마크다운 확장 관례(옵시디언 커스텀 상태)를 따른 것. 목록 들여쓰기는 스페이스 2칸.
- **의미**: ☐=해야 함 / ☑=완료 / ★=중요(오늘 반드시) / !=긴급·막힘. ★·!는 "완료 전" 상태라 오늘 화면·자동 표시에 별도 강조로 모은다.
- **승격 확장**: 지금은 `- [ ]`만 승격 가능 → `[ ]`·`[*]`·`[!]` 모두 가능하게. `!`로 승격하면 우선순위 높음을 미리 채운다 `[가정]`. 하위 불렛은 하위 할일(`parent_task_id`)로 승격 `[가정]`.
- **글자 입력으로도 항목 지정**(마우스 대신 텍스트): 승격 시 줄 안의 `키:값` 토큰을 사용자 정의 항목에 매핑한다. 예) `보고서 작성 요청자:김대리 납기:11-27 제품:A` → 항목 3개 채움. 단축 `@이름`(사람 타입 항목), `~11-27`(납기) `[가정]`. 정의되지 않은 키는 새 항목으로 만들지 묻는다(4.2.2).
- **구현 위험**: `Ctrl+1`은 Edge·Chrome·웨일에서 "N번째 탭으로 이동" 단축키와 겹쳐 페이지가 가로채지 못할 수 있다 → 구현 전 3개 브라우저에서 실측(P2B-01 프로토타입), 안 되면 `Ctrl+Alt+1` 또는 `Alt+1`로 대체하고 DECISIONS에 기록.
- 현재 칸 편집기는 일반 `textarea`다 → 줄 단위 텍스트 변환으로 구현 가능(서식 편집기 P3와 독립). 노트 페이지의 편집기(D-20)에도 같은 키를 나중에 이식.

### 4.2.2 사용자 정의 항목 (D-22, 신규)
> 요청자·우선순위·제품처럼 **그때그때 보고 싶은 항목이 바뀐다.** 현재 `tasks`의 `priority`·`requester` 고정 컬럼 구조로는 불가능 → 항목 정의를 데이터로 만든다.

- **항목(Field)** = `{key, label, type, options?, order}`. type: `choice`(선택지 버튼) / `multi`(복수 선택) / `text` / `person`(이전 입력값 자동 제안) / `date` / `number` / `check`.
- **기본 제공**(삭제·이름 변경 가능): 우선순위(choice 높음·보통·낮음), 요청자(person), 납기(date), 하기로 한 날(date). **제품**은 사용자가 만드는 예시로 제공하지 않고 "항목 추가"로 만든다.
- **선택지는 입력하다가 추가**: 칩 옆 `＋`로 새 선택지를 즉시 추가(D-12 — 드롭다운이 아니라 버튼). 선택지 순서·색·보관(숨김) 편집.
- **항목 관리 화면**(설정 안): 추가·이름·타입·선택지·순서·보관. 값이 있는 항목을 지우면 보관 처리(데이터 보존), 완전 삭제는 확인 후.
- **보기 연동**: 할일 화면의 필터 칩 줄과 행의 메타 칸은 **정의된 항목에서 자동 생성**된다(항목을 추가하면 필터가 생긴다). 항목별 표시/숨김, 필터 줄 표시 여부 설정.
- **저장**: 핵심 컬럼(title, status, parent, eval_id, page_path, note)은 그대로 두고, 사용자 정의 값은 `tasks.props` JSON(`{"requester":"김대리","product":"A"}`) + 정의는 `task_fields` 테이블 (5장). 기존 `priority`·`requester`·`due_date`·`planned_date` 데이터는 마이그레이션으로 props로 옮기되 API 필터 이름(`priority`, `requester`)은 호환 유지 `[가정 — P2B에서 확정]`.
- 평가 현황판의 값 항목(`eval_cells.fields`, 4.3)과 같은 사상이므로 타입 정의를 공통으로 쓴다.

### 4.2.3 하나의 데이터 · 구조 · 할일 페이지 위치 (2026-11-24 요청, 기준 화면 `web/design/prototype_v4.html`)
> 사용자 요청: "월간 일지는 텍스트 단위고 할일이랑 오늘은 별도로 되어 있다 — 다 연동이 돼야 의미가 있다." 그리고 유형·제품 같은 항목을 **지라 Structure처럼** 보고 끌어서 바꾸며, 항목을 나중에 추가·삭제할 수 있어야 한다.

**A. 일지 줄 = 할일 (단일 원본)**
- 일지 칸에서 표시가 붙은 줄(`[ ]`·`[x]`·`[*]`·`[!]`)은 곧 할일이다. 줄을 벗어나거나 칸에서 포커스가 빠지면 할일이 만들어지고, 줄 끝에 `^t<id>`가 붙는다(사람·LLM이 읽을 수 있는 블록 id). 표시 없는 줄은 그냥 메모.
  ```
  - [ ] LOT-TEST-002 리뷰 결과 정리 ^t14
    - B사 누락분 먼저              ← 메모 줄 (할일 아님)
  - [*] LOT-TEST-003 반복도 확인 ^t18
  ```
- 줄의 날짜 = 할일의 `하기로 한 날`. 할일 목록·오늘 화면·할일 페이지에서 체크·제목·하기로 한 날을 바꾸면 해당 일지 줄도 바뀐다(날짜가 바뀌면 줄이 그 날 칸으로 이동). 반대로 일지에서 체크하면 할일이 완료된다.
- 일지에서 `^t` 줄을 지우면 할일은 남기고 `하기로 한 날`만 비운다(토스트로 알림). 할일을 휴지통으로 보내면 일지 줄도 빠진다.
- 표시 줄 아래 들여쓴 표시 줄 = 하위 할일(`parent`). 줄 안 `@사람`·`~11-27`·`!`·`항목:값` 토큰은 생성 시 항목으로 옮기고 줄에서는 지운다. 없는 선택지는 만들고 알린다.
- '오늘' 화면의 일지 칸은 월간 일지의 오늘 칸과 **같은 편집기·같은 데이터**다. 일지 화면 옆 "날짜 없는 할일"을 칸에 끌어 놓으면 그날로 잡힌다.

**B. 줄 편집기 (일지·오늘·노트·할일 페이지 공통)** — 4.2.1의 키 + 다음 동작
- **더블클릭 접기**: 하위 줄이 있는 줄(또는 제목)을 더블클릭하면 하위를 접고 `⋯ n줄`을 표시한다. 하위가 없는 줄의 더블클릭은 일반 단어 선택. 접힘 상태는 보기 설정이며 파일에 쓰지 않는다(4.1과 같음). 줄 왼쪽 여백의 ▸/▾를 눌러도 된다.
- **이미지 붙여넣기**: 기본은 자동 크기(본문 너비 안, 최대 높이 제한, 비율 유지). 마우스를 올리면 `자동 · 작게(240) · 보통(480) · 크게(720) · 원본 · [__]px` 막대가 뜨고, 오른쪽 아래 손잡이를 끌어 10px 단위로 조절한다. 저장: `![](files/img-….png){w=480}` (`w=auto` / `w=orig` / 숫자) `[가정 — 표기법 P3에서 확정]`.

**C. 할일 페이지 (Ctrl+N)**
- `Ctrl+N`(일반 탭에서 브라우저가 가로채면 `Alt+N`)으로 새 할일 + 페이지를 만들고 바로 제목 편집으로 들어간다. 기본값(아래 D)과 `하기로 한 날=오늘`이 채워져 오늘 일지에도 줄이 생긴다. 기존 할일도 상세에서 "페이지 만들기" 가능. 페이지 본문 = 할일 메모.
- 페이지의 트리 위치는 **위치 규칙**으로 정한다:
  - 규칙 = `만약 [항목] [이(가)|아님|값 있음|비어 있음] [값] 그리고 … → 경로 템플릿`. 위에서부터 처음 맞는 규칙 하나만 적용, 끌어서 순서 변경.
  - 템플릿 변수: `{연}` `{월}` `{에픽위치}` + **모든 항목 이름**(`{유형}` `{제품}` … 새 항목을 만들면 변수도 생김). 계층 값은 경로로 펼친다(`{제품}` = `HBM/HBM-A`). 값이 없으면 `미분류`.
  - 맞는 규칙이 없을 때 기본 위치: `일지 아래(일지/{연}/{연}년 {월}월)` / `유형별 폴더` / `할일 폴더` 중 선택.
  - 예) `유형=셋업 그리고 제품=HBM → MI 공정업무/셋업/{제품}`.
  - 폴더가 없으면 자동 폴더를 만든다(트리에 '자동' 표시). 할일의 항목이 바뀌면 페이지가 새 위치로 옮겨지고 토스트로 알린다.
  - 트리에서 페이지를 직접 끌어 놓으면 **위치 고정**(규칙보다 우선, 상세에서 해제).

**D. 빠른 추가 기본값**: 상세 입력에서 고른 값(하기로 한 날·에픽·모든 항목)이 다음 할일의 기본값이 된다(끄기·비우기 가능). 일지 줄에서 만들어지는 할일에도 같은 기본값을 쓴다.

**E. 구조 화면 (지라 Structure식)** — 사이드바 '구조'
- **구조 보기**: 묶는 순서 칩(예: `제품 › 유형`)으로 할일을 트리 표로 본다. 칩은 추가·삭제·끌어서 순서 변경. 묶음 행마다 개수·진행률·"여기에 할일".
  - 할일 행을 다른 묶음에 끌어 놓으면 그 묶음 경로의 값으로 바뀐다(예: `HBM › 셋업` → `DRAM › 이슈`). 묶음 행을 끌면 안의 할일 전체가 바뀐다. 모두 실행 취소 가능. 일지·페이지 위치에 바로 반영.
- **항목 관리**: 항목 카드(이름·타입·필터 줄/행 표시 토글). 선택지는 추가·이름 변경(더블클릭)·색·삭제. **끌어서 순서 변경, 가운데에 놓으면 하위 값**(계층 선택지 — 예: `HBM-A`를 `HBM` 아래로). 항목 카드도 끌어서 순서 변경(빠른 추가·속성 순서). 새 항목 추가 시 빠른 추가·필터·구조·규칙 변수에 즉시 나타난다.
  - 쓰는 할일·페이지가 있는 선택지를 지우면 **옮길 값을 먼저 고르게** 한다(또는 비우기). 항목 삭제는 값 보관(4.2.2).
- **페이지 위치 규칙**: C의 규칙 편집 + 할일 페이지별 현재 위치·근거(규칙 n / 기본 / 고정) 표.

**F. 페이지 트리 드래그 앤 드롭**: 행을 끌어 다른 행 위·아래(순서) 또는 가운데(하위로) 놓는다. 자기 하위로는 못 옮긴다. 할일 페이지·자동 폴더는 규칙/고정으로만 위치가 정해진다(F로 끌면 고정).

**데이터 모델 추가 `[가정 — 구현 작업에서 확정]`**: `tasks.has_page`(INTEGER), `tasks.page_pin`(TEXT, 고정 경로), `task_fields.options`의 선택지에 `parent`(계층), 위치 규칙은 `settings.page_rules`(JSON 배열) + `settings.page_fallback`. 일지 줄의 `^t<id>`는 파일 본문에 그대로 저장한다.

**할일 (tasks) — Q-04 잠정안**

  - 일지 → 할일: `PUT /api/journal/{yyyy-mm}/{dd}`가 저장 전에 그날의 연결 줄을 동기화한다(제목, `[x]` 완료, `[*]`·`[!]` 표시, 붙여넣어 옮긴 줄 = 계획일 변경). 같은 ID가 두 줄이면 뒤 줄은 연결을 푼다(복제로 이슈가 늘지 않음). 줄이 사라지면 그날의 계획 연결만 해제(할일은 남음). 응답 `{..., content(정규화된 본문), changed:[id], other_days, tasks}`.
  - `GET /api/journal/{yyyy-mm}`에 `tasks: {id: task}`(그 달 연결 할일) 추가.
  - 승격 `POST /api/todos/from-line`: `[ ]`·`[x]`·`[*]`·`[!]` 줄 지원(`*`→mark star, `!`→mark urgent+우선순위 1, `x`→done). 같은 날 같은 제목의 열린 할일이 있으면 새로 만들지 않고 연결(`reused:true`); 그 할일이 이미 그날 줄에 연결돼 있으면 409. 응답에 `tasks`.
  - `GET /api/todos` 추가 필터: `ids=1,2`, `planned_from`/`planned_to`, `due_from`/`due_to`(양끝 포함), `unplanned=true`, `marked=true`, `open_only=true`. `mark`는 `POST/PATCH`로도 받는다(`star`·`urgent`·null).

### 4.3 평가 현황판 (board 타입, P4)

**템플릿 (eval_templates)**
- `stages`: 순서 있는 단계 목록 `[{key, label, color, warn_hours}]` — 편집 가능.
  마스터 기본값: 검사대기 → 검사완료 → 리뷰대기 → 리뷰완료&분류대기 → 분류완료 → 정리완료
- `fields`: 칸에 넣는 값 항목 `[{key, label, type}]`, type = `number | text | okng | check`
  마스터 기본값 `[가정]`: 반복도(okng), scan time(number, 분), 디펙 모수(number), 분류 완료(check), 이슈(text)
- 평가 생성 시 템플릿을 **복사**해서 그 평가에서만 고친다 (마스터는 안 바뀜). "이 평가 구성을 새 마스터로 저장" 버튼.
- P4-02 마이그레이션 006이 기본 마스터 하나를 설치한다. 기본 경고 시간은 `null`(경고 비활성)이다. 단계 색은 `#RRGGBB`, 경고 시간은 양수 또는 `null`이다. 단계는 하나 이상이며 단계 키와 값 항목 키는 각 목록에서 고유하다.
- 템플릿 API: `GET /api/eval-templates` → `{items: [{id, name, is_master, stages, fields}]}`(마스터 먼저). `POST /api/eval-templates`는 `{name, stages, fields?, is_master?}`를 받아 생성된 항목을 201로 돌려준다. `PATCH /api/eval-templates/{id}`는 보낸 항목만 고치고 전체 갱신 항목을 돌려준다. 단계·값 항목은 배열 단위로 바꾼다. `is_master: true`는 하나의 트랜잭션에서 기존 마스터를 교체하고, 현재 마스터만 해제하는 요청은 409를 돌려준다.

**평가 만들기 (마법사)**
1. 템플릿 선택 2. 설비 목록 붙여넣기 3. Lot·웨이퍼 붙여넣기(`LOT-TEST-001  1,2,3` 형식 또는 엑셀 2열) 4. 제외할 조합 끄기 → 칸 자동 생성.
- 사이드바 **평가 현황판 → 평가 만들기** 또는 페이지 추가에서 **현황판**을 선택한다. 기본 위치는 기존 `MI 공정업무/설비사 평가`, 기존 `MI 공정업무`, 루트 순서다. 페이지 추가로 들어오면 선택한 부모에 만든다.
- 설비는 한 줄당 하나이며 탭 두 번째 열은 설비사(선택)다. Lot의 반복 행은 하나의 Lot으로 합치고 웨이퍼 문자열은 앞자리 0을 포함해 유지한다. 중복 설비·웨이퍼와 빈 조합은 오류로 처리한다. 평가당 설비 1~10개, Lot 1~20개, Lot당 웨이퍼 1~25개다.
- `POST /api/evaluations` 입력은 `{name, template_id, equipment:[{name,vendor?}], lots:[{lot_no,wafers:[string]}], excluded?:[{equipment,lot_no,wafer_no}], parent?:string, request_id?:uuid}`다. 응답 `{created, evaluation}`에 평가 ID, 페이지 경로, 복사한 단계·값 정의, 상태와 조합 수가 들어 있다. `GET /api/evaluations`는 `{items}`, `GET /api/evaluations/{id}`는 개별 요약이다.
- 007은 요청 ID와 표준화한 입력 해시를 저장한다. 같은 입력의 같은 ID는 기존 평가를 200으로 돌려주고 다른 입력에 ID를 재사용하면 409다. 제외 조합의 전달 순서는 해시에 영향을 주지 않는다.
- 평가·설비·Lot·웨이퍼·칸은 한 SQLite 트랜잭션에서 만든다. 제외한 조합도 `excluded=1`로 보존한다. 모든 신규 칸은 `stage_key=NULL`이며 첫 배정과 이력 기록은 단계 전환에서 시작한다. 연결된 노트 금고 페이지는 `board` 타입과 `eval_id`를 가지며, 생성 중 실패하면 등록을 되돌리고 새로 만든 페이지를 휴지통으로 옮긴다. 페이지가 이동하거나 휴지통으로 가면 DB의 경로도 갱신된다.

**현황판 화면**

- 상단 **보기 버튼**(토글 칩): `설비별` `Lot별` `단계별` `남은 것만` `값 보기`.
- **구현 (P4-04)**: `GET /api/evaluations/{id}/board` → `{evaluation, equipment:[{id,name,vendor}], lots:[{id,lot_no,wafers:[{id,wafer_no}]}], cells:[{id,equipment_id,wafer_id,stage_key,excluded,values,note,at}]}`. `at`는 `eval_stage_log` 최신 이력 시각(없으면 null)이며 셀에는 저장하지 않는다(D-09).
  - 보기 칩: `설비별`(Lot 띠 + 웨이퍼 행 × 설비 열, 키보드 그리드) · `Lot별`(Lot × 설비, 단계 분포 막대와 완료 수, Lot 이름을 누르면 설비별 보기로 이동) · `단계별`(단계 열마다 칸 목록, 열당 120칸 후 더 보기). `남은 것만`은 마지막 단계 칸과 제외 칸을 숨기는 토글. `칸 표시`(설비별 전용)는 단계 또는 값 항목 하나를 칸에 보여 준다. `값 보기`는 이 `칸 표시`의 값 항목 칩이 맡는다. 선택은 `localStorage`의 `mi.board.prefs`에만 저장한다.
  - 상단 요약: 진행률(마지막 단계 칸 / 제외 칸을 뺀 전체), 단계 분포 막대·범례, 설비 열 머리글에 설비별 진행률. 칸을 누르거나 Enter/Space를 누르면 `board-cell` 이벤트(`detail.id`)를 낸다(P4-05가 패널을 연결).
- 칸 클릭 → 옆 패널에서 단계 버튼으로 전환 + 값 입력 + 메모.
- **다중 선택 일괄 전환**: 행·열·드래그로 여러 칸 선택 → 단계 버튼 한 번.
- **구현 (P4-05)**: 선택이 패널을 결정한다(0칸 닫힘 · 1칸 상세 · 2칸 이상 일괄). 선택 규칙: 클릭=한 칸, Ctrl/Cmd+클릭=추가·해제, Shift+클릭·Shift+방향키=앵커에서 사각형, 마우스 드래그=사각형, 열·행·Lot 머리글 클릭=전체(Ctrl/Shift는 추가), 방향키=이동(패널이 열려 있으면 선택도 따라감), Ctrl+방향키=선택 유지한 채 이동, Space=추가·해제, Enter=선택 + 패널로 포커스, Ctrl+A=표시 중인 모든 칸, Ctrl+Shift+방향키=끝까지 확장, Esc=해제(패널 안에서는 표로 복귀). 패널의 '선택 범위' 칩(이 웨이퍼 행·이 설비 전체·이 Lot 전체·모두)은 키보드용 대안이다. 단계별 보기 목록도 같은 규칙을 쓴다.
  - 제외한 칸은 범위·열·행·전체 선택에서 빠지고(개수 안내), 단독 클릭하면 읽기 전용 안내만 보인다.
  - 단일 칸 패널: 단계 칩(즉시 전환) · 다음 단계 버튼 · 값 입력(number/text는 Enter·포커스 이동 때 저장, okng·check는 칩 토글) · 메모(포커스 이동·Ctrl+Enter 저장, 2,000자) · 단계 이력(`eval_stage_log`, 최신순). 저장 상태는 패널 하단에 표시한다.
  - 일괄 패널: 지금 단계 분포 · 옮길 단계 칩을 고른 뒤 '옮기기' 버튼 · '각 칸을 다음 단계로'. 이미 같은 단계인 칸은 그대로 두고 알려 준다. 결과는 토스트의 **되돌리기**로 취소한다(되돌리기도 새 이력으로 남는다).
  - API: `POST /api/evaluations/{id}/cells/stage`는 `{cell_ids:[...], stage_key}`(`null`=미배정) 또는 `{moves:[{cell_id, stage_key}]}` 중 하나를 받아 한 트랜잭션에서 처리한다(최대 5,000칸). 없는 칸(404)·다른 평가의 칸(404)·제외 칸(409)·없는 단계(422)·중복 칸(400)이 하나라도 있으면 아무것도 바꾸지 않는다. 응답 `{changed:[{id,from,to}], unchanged:[id], at}`이며 실제로 바뀐 칸만 `eval_stage_log`에 기록한다. `PATCH /api/eval-cells/{id}`는 `{values?:{key:value|null}, note?:string}`을 병합 저장한다(number 유한 숫자, okng `ok|ng`, check bool, text 500자, 메모 2,000자, `null`·빈 값은 삭제, 제외 칸 409). `GET /api/eval-cells/{id}/history` → `{items:[{id,from_stage,to_stage,at}]}`(최신순 50건).
- **구현 (V-005) — 설비·Lot 상태 편집**: 마이그레이션 011이 `eval_equipment`·`eval_lots`에 `status TEXT NOT NULL DEFAULT 'active' CHECK IN ('wait','active','hold','done')`(대기·진행·보류·완료)과 `note TEXT`(500자)를 추가한다. 상태는 사람이 붙이는 라벨이라 단계·진행률·대기 시간 계산에 쓰지 않는다(D-09 유지). 보드 응답의 `equipment[]`·`lots[]`에 `status`·`note`가 붙는다.
  - API: `PATCH /api/evaluations/{id}` `{status: active|hold|done}`(평가 상태) → `{from, status}` · `PATCH /api/evaluations/{id}/equipment/{eid}` `{name?, vendor?, status?, note?}` · `PATCH /api/evaluations/{id}/lots/{lid}` `{lot_no?, status?, note?}` → `{id, kind, name, status, note, vendor?}`(보낸 키만 바꿈, 이름 중복 409·빈 이름/없는 상태 422·다른 평가의 대상 404·바꿀 내용 없음 400) · `POST /api/evaluations/{id}/status` `{targets:[{kind:equipment|lot, id, status}]}` → `{changed:[{kind,id,from,to}], unchanged:[{kind,id}]}`(한 트랜잭션, 하나라도 잘못되면 전부 취소) · `POST /api/evaluations/{id}/cells/exclude` `{cell_ids, excluded}` → `{changed:[id], unchanged:[id], excluded, at}`(원자적, 평가할 칸이 하나도 안 남으면 409). 제외해도 `stage_key`는 그대로이고, 포함으로 되돌릴 때 단계가 있는 칸에는 `eval_stage_log`에 같은 단계로의 재진입 한 줄을 남겨 제외돼 있던 시간이 대기로 잡히지 않게 한다(D-09).
  - 화면: 설비 열 머리글·Lot 띠·Lot별 보기 머리글에 **아이콘+글자 상태 배지**(대기 ◔ 점선 · 진행 ▷ · 보류 ❚❚ · 완료 ✓, 색만으로 구분하지 않음). 배지를 누르면 팝오버(상태 칩 — `1`~`4` 키, 이름, 설비사(설비만), 메모; Enter 저장·Esc 닫기·포커스 복귀·바깥 클릭 닫기), 헤더 이름 더블클릭은 이름 입력에 포커스, 칸에서 `E`/`L`은 그 칸의 설비/Lot 팝오버. 요약의 평가 상태 배지(진행 중·보류·완료)도 같은 팝오버. 칸 패널(단일)에 `설비 · Lot` 행(배지+편집 버튼), 다중 선택 패널에 선택한 칸이 속한 설비 N개·Lot M개 일괄 상태 칩(섞여 있으면 분포 표시)과 `선택한 N칸 평가에서 제외`, 제외한 칸 패널에 `평가에 포함하기`. 단계별 보기 카드에는 "진행"이 아닌 설비·Lot 상태만 작은 태그로 표시. 상태·이름·제외 변경은 모두 토스트 `되돌리기`로 취소한다. `남은 것만` 필터는 칸 기준 그대로다(상태 완료 Lot·설비를 숨기지 않음).
  - 엑셀: `칸 목록`에 `설비 상태`·`Lot 상태` 열(대기 상태 다음), `요약` 시트 아래에 설비·Lot 상태·메모 표.

**대기 시간 (v0.1 queue_items 대체)**
- 단계 전환마다 `eval_stage_log`에 기록 → 현재 단계에 머문 시간 = 지금 − 마지막 전환 시각.
- 단계마다 `warn_hours` 초과 시 주황, 2배 초과 시 빨강. "오늘" 화면에 오래 머문 칸 Top N.
- **구현 (P4-06)**: 규칙은 `app/eval_wait.py`(서버)와 `web/js/eval-wait-model.js`(화면, 같은 규칙)에 있다. 대기 시간은 **저장하지 않고** 조회 때마다 계산한다(D-09).
  - 대기 = 지금 − 그 칸의 최신 `eval_stage_log` 진입 시각(달력 시간 기준, 영업일·주말 제외 없음). 최신 이력의 `to_stage`가 칸의 현재 단계와 다르거나 이력이 없으면 "알 수 없음"(`wait_h: null`). 단계를 되돌려 다시 들어가면 시계가 다시 시작한다. 제외 칸·미배정 칸·마지막 단계 칸은 대기하지 않는다. 시각 문자열에 오프셋이 없으면 Asia/Seoul(+09:00)로 읽고, 미래 시각은 0으로 본다.
  - 경고 단계: `warn_hours`를 **초과**하면 1(경고), 2배를 **초과**하면 2(심각). `warn_hours`가 비어 있으면 경고 없음. 기준은 평가가 복사해 둔 단계(`evaluations.stages[].warn_hours`)에 저장하며 칸마다 저장하지 않는다.
  - `GET /api/evaluations/{id}/board`: 응답에 `now`(서버 시각, ISO +09:00)가 추가되고 칸마다 `wait_h`(소수 2자리 시간, 또는 null)와 `warn`(0·1·2)이 붙는다. 화면은 `now`와 PC 시계의 차이를 보정해 `at`으로 다시 계산한다. `?now=`는 없다(테스트는 `repo.get_board(conn, id, now)`).
  - `PUT /api/evaluations/{id}/warn-hours` `{warn_hours: {단계키: 시간 | null}}` → `{stages}`. 보낸 단계만 바꾸며 0 초과 8,760 이하 숫자 또는 null(끔). 없는 단계 422, 형식 오류 422, 없는 평가 404.
  - 화면: 토글 칩 `대기 경고`(기본 켬, 브라우저 설정 `mi.board.prefs.warn`)과 `경고 기준` 칩(단계별 시간 입력 패널, 마지막 단계는 제외). 경고 칸은 색에만 의존하지 않는다: 경고 = 시계 아이콘 + 대기 시간 + 점선 테두리 배지·위쪽 가는 선, 심각 = 경고 삼각 아이콘 + 대기 시간 + 실선 굵은 테두리 배지·위쪽 굵은 선, 칸 `aria-label`에 "대기 3일 (경고: 기준 24시간 초과)" 문장 포함. 설비별 보기는 칸 안 배지, Lot별 보기는 칸의 경고·심각 개수 배지, 단계별 보기는 단계 안에서 오래 기다린 칸부터 정렬하고 대기 시간을 표시한다.
  - 요약: 가장 오래 기다리는 칸(항상 표시)과 경고·심각 칸 수·단계별 최장 대기(경고 켬일 때). 칸 패널: 단일 칸에 대기 배지(켬이면 경고 문구 포함)와 이력 항목별 "머문 시간", 다중 선택에는 가장 오래 기다린 칸과 경고 수.
  - 자동 갱신 없음: 화면을 연 채로 시간이 지나도 `새로고침`이나 단계 변경 전까지 대기 시간은 그대로다.
- **템플릿 편집·엑셀 내보내기 구현 (P4-07)**
  - `GET /api/eval-templates/{id}/usage` → `{template_id, evaluation_count, stages:{단계키:{evaluations, cells}}}`: 평가는 템플릿의 복사본이라 연결 행이 없고, 단계 키가 같은 평가 수와 지금 그 단계에 있는 칸(제외 제외) 수를 센다. `DELETE /api/eval-templates/{id}`는 마스터가 아닐 때만 지우며(마스터 409, 없으면 404) 이미 만든 평가는 그대로다.
  - `POST /api/evaluations/{id}/save-as-template` `{name, is_master?=true}` → 201 템플릿. 그 평가가 가진 단계(경고 기준 포함)·값 항목을 새 템플릿으로 복사한다. 마스터로 저장하면 기존 마스터는 일반 템플릿이 된다.
  - 화면: 평가 현황판 목록의 `템플릿 편집`(`web/js/eval-templates.js`, 모델 `eval-template-model.js`). P2B-07과 같은 초안 방식: 편집은 초안에서만, `적용`(한 번의 PATCH)·`취소`/Esc/바깥 클릭은 서버를 건드리지 않고 버림. 초안이 있으면 다른 템플릿으로 전환·복사가 막힌다. 단계 추가·이름 바꾸기·↑↓/Alt+↑↓로 순서·삭제(사용 중이면 영향 확인 창)·단계별 경고 기본 시간(비우면 끔)·색 고르기(색 이름 병기, 번호와 이름이 항상 같이 보임), 값 항목 추가·이름·입력 방식 토글 칩(숫자/글자/OK·NG/체크)·순서·삭제. 단계 키는 이름을 바꿔도 유지되고 새 단계는 `stage_N`, 새 값 항목은 `field_N`. 이름·경고 시간 오류가 있으면 적용 불가. 드롭다운 없음(D-12). 평가 현황판 요약의 `새 마스터로 저장`은 위 save-as-template을 부르는 창이다.

### 4.4 Lot 상태 (MOS) (P4)
- **붙여넣기 어댑터**: MOS 화면에서 복사한 표를 붙여넣으면 Lot 번호·step·Hold·위치를 읽어 `lot_status`에 시각과 함께 저장. 열 매핑은 처음 한 번 지정.

- **구현 (P4-08, 평가 칸 단계 갱신 범위)**: `lot_status` 저장·Lot 배지는 아직 없다(Q: MOS의 step/Hold/위치 열을 실제 화면으로 본 뒤 결정). 대신 붙여넣은 표로 **평가 칸의 단계**를 갱신한다.

  - **열 매핑**은 머리글 이름으로 찾고(대소문자·띄어쓰기·`_`·`-` 무시, 쉼표로 여러 이름) `settings.mos_mapping`(JSON 문자열: `lot`·`wafer`·`equipment`·`stage`·`time` 이름 목록 + `stageMap {MOS 값: 평가 단계 이름}`)에 저장한다. 필수는 Lot·설비·단계, 웨이퍼·시각은 선택(웨이퍼 열이 없거나 비면 그 Lot의 모든 웨이퍼, `01`·`W1`·`1-3`·`01,03` 허용). 단계 값은 평가 단계 이름·키 또는 `stageMap`으로 찾는다. 시각은 `2026-11-24 09:30[:15]`·`2026/11/24`·`2026.11.24`·`20261124093015`·ISO·`오전/오후`·AM/PM, 오프셋이 없으면 Asia/Seoul.
  - **덮어쓰지 않는 규칙**: 줄마다 칸별로 `적용`(미배정이거나 앞 단계로 진행)·`이미 같음`·`단계 되돌림`·`MOS가 더 오래됨`(MOS 시각이 칸의 최신 이력보다 이전)·`뒤의 줄이 덮어씀`(같은 칸이 여러 줄이면 더 늦은 MOS 시각, 시각이 없으면 뒤의 줄)·`제외`로 분류한다. 되돌림·오래됨은 **기본으로 건너뛰고** 토글 칩으로 켜야 적용한다. 이 평가에 없는 Lot·설비·웨이퍼·단계, 읽을 수 없는 시각, 빈 필수 값은 줄 오류로 목록에 보이고 건너뛴다.

### 4.6 RCP 관리 (P6) — 읽기 전용 우선 (D-11)
- **수집**: FTP 경로 등록(설비·라인별) + **이름 필터**(예: `aabb` 포함) → 해당 레시피의 파라미터 파일만 로컬 캐시로 내려받음. Python 표준 `ftplib`.
- **파싱 (2단 구조)**:
  1. **범용 파서 내장**: XML(경로 평탄화 `Inspection/Optics/Focus`), INI(`[섹션] 키`), TXT(`키=값`, `키: 값`, 탭 구분) → `{파라미터 경로: 값}`. 대부분 이걸로 읽힌다.
  2. **설비사별 매핑 파일** `parsers/<vendor>.json`: 어떤 파일을 어떤 파서로 읽을지, 보여줄 파라미터·한글 이름·단위·묶음. 범용 파서로 안 되는 형식만 `parsers/<vendor>.py`.
  - 매핑 파일·파서는 LLM과 대화하며 만든다(스킬 `recipe-parser-maker`, 회사에서).
- **보기**: 파라미터 비교 표 — 같은 레시피의 설비·라인 간 차이 강조.
- **이력**: 수집할 때마다 스냅샷 → 바뀐 파라미터 감지·diff.
- **수정·업로드 (마지막 단계)**: 자동 백업 → diff 미리보기 → 명시적 확인 → 업로드 → 로그. 기본은 꺼둠(설정에서 켬).

### 4.6.1 RCP 설계 상세 (P6-01, D-36)
**원칙**: 설비 쪽으로는 읽기만(D-11). 앱이 쓰는 곳은 `data/` 아래 로컬 캐시와 DB뿐. 주소·계정은 DB·로그·화면에 남기지 않는다.

**1) FTP 접속 정보 — `config/local.json`(git 제외)에만**
```json
"recipe_ftp": { "profiles": { "line1": {
  "host": "…", "port": 21, "user": "…", "password_env": "MI_RCP_FTP_PW",
  "encoding": "cp949", "passive": true, "timeout": 20, "allow_write": false } } }
```
- 소스(`recipe_sources.ftp_profile`)는 프로필 **이름**만 가진다. 비밀번호는 `password_env`(환경 변수) 우선, 없으면 `password`. 오류 메시지·수집 로그에 호스트·계정을 넣지 않는다.
- `rcp_enabled`가 꺼져 있으면 수집하지 않는다(외부 연결 0건 유지, 9장 예외는 켰을 때만).

**2) 수집 흐름 (P6-02, `ftplib`)**
1. 실행 기록 `recipe_runs`(status `running`) 생성 → 프로필로 접속. 읽기 전용 래퍼는 `cwd/pwd/nlst/mlsd/dir/retrbinary`만 노출하고 `stor*/delete/rename/mkd/rmd`는 없다(테스트로 확인).
2. `remote_dir` 목록 → **이름 필터**를 통과한 레시피만(`layout=folder`: 하위 폴더 = 레시피, `file`: 파일 = 레시피).
3. 레시피마다 `file_globs`에 맞는 파일만 `data/recipes/.tmp/<run_id>/`에 `.part`로 받기 → 크기·sha256 → `blobs/<sha[:2]>/<sha>`로 이동(이미 있으면 버림).
4. 내용 해시 = 정렬된 `rel_path NUL sha256` 줄들의 sha256. 현재 스냅샷과 같으면 `last_seen_at`만 갱신(`unchanged`), 다르면 새 스냅샷 + 파일 + 파싱한 파라미터(`add_snapshot`).
5. **성공한 전체 실행**에서 안 보인 레시피는 `missing=1`(삭제하지 않음). 부분 실패 실행은 missing 표시를 하지 않는다.
6. 한도: 실행당 파일 2,000개·파일 20MB·합계 500MB(설정 가능), 타임아웃, 연결 1개 순차, 취소(`cancelled`). 원격 이름의 `..`·절대 경로·`\`·제어 문자는 거부(로컬 경로는 해시로만 만들므로 경로 이탈 없음).
7. 결과를 `recipe_runs`에 기록(listed/matched/downloaded/unchanged/new_snapshots/errors[{recipe, file, 메시지}]).

**3) 이름 필터 규칙** — `name_filter` JSON 목록 `[{type, value, exclude}]`
- `type`: `contains`·`prefix`·`suffix`·`glob`(대소문자 무시). **정규식은 받지 않는다**(ReDoS·실수 방지). 규칙 30개·값 120자 이하.
- 포함 규칙이 없으면 전부 포함, 있으면 하나라도 맞아야 포함. 제외 규칙이 하나라도 맞으면 제외. 예: plan `aabb_bb100000` 관리 → `[{"type":"contains","value":"aabb"},{"type":"suffix","value":"_old","exclude":true}]`.
- 구현: `app/repositories/recipes.py` `validate_filter`·`name_matches`.

**4) 로컬 캐시 (`data/recipes/`, git 제외 — vault 아님)**
```
data/recipes/blobs/<sha[:2]>/<sha256>          원본 파일, 내용 주소·불변(스냅샷 간 공유)
data/recipes/.tmp/<run_id>/                    받는 중(.part → 검증 → blobs로 이동, 실행 끝나면 삭제)
data/recipes/backups/<시각>_<소스>_<레시피>/   P6-05 쓰기 직전 원본 + manifest.json(sha256)
data/recipes/write_log.jsonl                   P6-05 쓰기 감사 로그 사본(추가만)
data/recipes/.trash/                           정리된 blob (바로 지우지 않음)
```
파일 이름·경로는 DB(`recipe_files.rel_path`)에 있으므로 사람·LLM은 API·CLI(P7)로 원래 이름과 함께 본다.

**5) 파서 플러그인 (`parsers/`, D-19)**
- `parsers/base.py`: `RecipeParser`(`name`, `version`, `extensions`, `can_write=False`, `sniff(file_name, head)`, `parse(bytes, file_name) → ParseResult{params[Param(path, value, line)], warnings, encoding}`), `register`·`get`·`pick`·`names`, `ParseError`(한국어 메시지), `decode_text`(UTF-8(BOM) → CP949 → Latin-1). 공통 검사: 20MB·파라미터 5만 개·경로 중복 거부.
- 파서는 순수 함수(네트워크·파일 쓰기 없음). **경로 표기(P6-03 확정)**: XML `A/B/C`(루트 요소 이름은 뺌, 속성 `A/B@attr`, 같은 이름 형제는 첫째 `A/B`·둘째부터 `A/B[2]`·`A/B[3]`, 네임스페이스 제거, 하위 요소가 있는 요소의 본문 글자는 경고만 하고 버림), INI `섹션/키`(섹션 앞 키는 `키`, 중복 키 `키[2]`), TXT `키`(표 모드 `행키/열이름`, 고정폭 모드 `이름`, 중복 `[2]`). 경로 안의 `/`는 `_`로 바꾼다.
- 내장 파서(`parsers/generic.py`, `parsers/__init__`이 등록): `xml`(`.xml`)·`ini`(`.ini .cfg .conf`, 줄 번호 보존을 위해 configparser 대신 직접 읽음)·`txt`(`.txt .prm .par`). 인코딩은 UTF-16(BOM) → UTF-8(BOM) → CP949 → Latin-1, NUL 바이트가 있으면 바이너리로 거부. **XML 안전**: `<!DOCTYPE`·`<!ENTITY`가 있으면 전체 거부(디코딩한 전체 텍스트에서 검사), 깊이 64·요소 10만 개·파라미터 5만 개·파일 20MB 한도, 선언된 `encoding=`은 이미 디코딩했으므로 제거하고 파싱. 파서 옵션(`options`)은 매핑 파일 `files` 규칙에서 받아 파서가 검증한다: xml `key_attr`(예: `<Param Name="Focus">1</Param>` → 경로 `…/Focus`), txt `mode`=`kv`(기본, `키 = 값`·`키: 값`·`키<TAB>값`, 주석 `# ; //`)·`table`(`delimiter` `,` `;` `|` `tab`, 기본 공백; 첫 줄이 머리글)·`fixed`(`name_cols`·`value_cols` = [시작, 끝) 열 번호). `parsers/fake.py`는 테스트 전용(`.fake`, 기본 import 안 됨).
- `version`이 바뀌면 캐시 blob에서 다시 파싱해 해당 스냅샷의 `recipe_params`만 다시 만든다(새 스냅샷 아님, `parser_info`에 파서·매핑 버전 기록).
- **파싱 연결(P6-03, `app/rcp_parse.py`)**: 수집이 새 버전(내용 해시가 현재와 다름)을 만들 때만 파일마다 `parse_one`을 돌린다(변화 없으면 파싱 생략). 파서는 매핑 `files` 규칙 첫 일치, 없으면 확장자(`pick`), 그것도 없으면 파싱 대상 아님(원본만 보관, 오류 아님). **어떤 파일이 실패해도 수집은 멈추지 않는다**: 한국어 메시지가 `recipe_files.error`에 남고(예상 못 한 예외는 고정 문구만, 내부 문구·경로 비노출), 스냅샷 `parse_status` = `ok`(오류 0, 하나 이상 파싱) / `partial` / `error`(전부 실패) / `unparsed`(적용된 파서 없음). 파싱 실패는 실행 `errors`에 `파싱 실패: …`로 보이지만 실행 상태·`missing` 판단에는 영향이 없다. `parser_info` = `{mapping, mapping_version, mapping_auto, parsers{이름:버전}, warnings(최대 50), warning_count, parsed_at, mapping_error?}`.

**6) 설비사 매핑 파일** — `parsers/mappings/<이름>.json`(가짜 예시만 커밋) + `config/recipe_mappings/<이름>.json`(git 제외, 회사 실제 매핑, 같은 이름이면 우선)
```json
{ "format": "mi-planner-recipe-mapping", "format_version": 1,
  "vendor": "VENDOR-X", "models": ["MODEL-1"], "mapping_version": "2026-11-24.1", "description": "…",
  "files":  [{"match": "*.xml", "parser": "xml"}, {"match": "params/*.ini", "parser": "ini"}],
  "params": [{"path": "Inspection/Optics/Focus", "label": "초점", "unit": "um", "group": "광학", "compare": "number", "tolerance": 0.01},
             {"path_glob": "Inspection/Detect/*/Threshold", "label": "임계값", "group": "검출"}],
  "ignore": ["Header/*", "*/Timestamp"], "show_unmapped": true }
```
- 들여쓴 JSON(사람·LLM이 메모장으로 고침). `files`는 위에서부터 첫 일치(`/` 없는 패턴은 파일 이름에만, 대소문자 무시; 규칙에 `options` 객체를 둘 수 있음), 없으면 `pick`(확장자). `params` 순서 = 표시 순서. `ignore`는 비교·표시 제외. 더 높은 `format_version`은 "앱 업데이트" 안내로 거부. 검증: `parsers/mapping.py` `validate`·`load`.
- **적용 순서(P6-03, `parsers/mapping.py` `apply`)**: `ignore` 글롭(대소문자 무시, `*`는 `/`도 포함)에 맞는 경로 제거 → `params`에 처음 맞는 규칙(`path` 정확히 또는 `path_glob`)으로 `label`·`unit`·`group` 부여 → **매핑된 것이 `params` 순서대로 먼저, 나머지는 파일 순서**(`show_unmapped: false`면 나머지 숨김). `compare: number`인데 숫자가 아닌 값은 경고. 매핑이 없으면 파서 결과를 그대로 저장.
- **매핑 선택**: 소스의 `mapping` 이름 → 비어 있으면 같은 `vendor`(대소문자 무시)이고 `models`가 비었거나 소스 `model`이 들어 있는 첫 매핑(이름순) → 없으면 매핑 없이 확장자로 읽음. 이름이 있는데 파일이 없거나 깨졌으면 매핑 없이 읽고 `parser_info.mapping_error`·실행 메시지로 알린다. 예시(가짜): `parsers/mappings/example_vendor.json`·`example_xml_vendor.json`(`key_attr`)·`example_ini_vendor.json`(`show_unmapped: false`)·`example_txt_vendor.json`(고정폭·표). 가짜 레시피 파일은 `scripts/make_sample_recipes.py`.
- 스킬 `recipe-parser-maker`(P7)는 이 형식의 파일을 만든다.

**7) 스냅샷·diff 의미**
- 레시피 신원 = (소스, 레시피 이름). 버전 = 내용 해시. 현재 스냅샷과 해시가 같으면 새 스냅샷을 만들지 않고, 다르면(되돌림 A→B→A 포함) 새로 만든다. 스냅샷은 지우지 않는다(작음).
- 비교 키 = (파일 `rel_path`, 파라미터 `path`). 상태: `same`·`changed`·`added`·`removed`. 값은 앞뒤 공백을 뺀 문자열로 비교, 매핑 `compare: number`면 숫자로(±`tolerance`).
- 이력 diff = 같은 레시피의 두 스냅샷(기본: 현재 vs 직전). 설비·라인 비교 = 같은 레시피 이름의 여러 소스 현재 스냅샷을 열로 놓고 다른 값 강조(P6-04).
- 파싱 실패 파일은 파일 해시 수준으로만 비교("파일 바뀜, 파라미터 비교 불가").

**8) 레시피 쓰기 안전장치 설계 (P6-05 — 지금은 쓰기 코드 없음, D-11)**
- **두 개의 열쇠**: 설정 `rcp_write_enabled=on`(UI, `rcp_enabled=on`일 때만 켤 수 있고 RCP를 끄면 같이 꺼짐) **그리고** 프로필 `allow_write: true`(config/local.json, 화면에서 못 바꿈). 하나라도 없으면 쓰기 API는 403. CLI(P7)·LLM 스킬에는 쓰기 명령을 만들지 않는다.
- **흐름**: 초안 편집(파라미터 값만, 파일 생성·삭제·이름 변경 없음) → 원본 바이트에서 바뀐 줄만 고친 새 파일 생성(인코딩·줄바꿈·BOM·순서 보존, `can_write` 파서만) → 새 파일을 다시 파싱해 **의도한 파라미터만** 바뀌었는지 검증 → 설비에서 방금 다시 받은 파일 해시가 초안 기준 스냅샷과 같은지 확인(다르면 중단: "설비에서 바뀌었어요") → 원본 백업 저장·해시 검증 → **diff 미리보기**(파라미터 표 + 텍스트 줄) → **명시적 확인**(소스·설비·라인·경로 표시 + 레시피 이름 직접 입력) → 기본은 **dry run**(업로드만 빼고 전부 실행) → 업로드 → 다시 받아 해시 검증, 다르면 백업으로 자동 복구 시도 → **감사 로그** → 새 스냅샷 수집.
- 한 번에 파일 1개, 일괄 쓰기 없음. 감사 로그는 추가만(새 마이그레이션 테이블 + `write_log.jsonl`), 삭제 API 없음. 로그 항목: 시각, 소스·레시피·파일, 기준 스냅샷, before/after sha256, 백업 경로, 바뀐 파라미터, dry_run 여부, 결과·오류.
- **위협·실패 목록과 대응**

  | # | 위협·실패 | 대응 |
  |---|---|---|
  | T1 | 실수 클릭·잘못 켠 설정 | 두 열쇠 + 이름 직접 입력 확인 + 기본 dry run |

### 4.6.2 수집 구현 (P6-02, D-37)
- **설정 파일**: `app/config.py`가 `config/local.json`을 읽는다(없으면 빈 설정). 프로필은 `host·port·user·password(_env)·encoding·passive·timeout`, 선택 `recipe_ftp.limits`(`max_files`·`max_file_bytes`·`max_total_bytes`·`max_seconds`·`max_depth`). 화면·API에는 프로필 **이름·encoding·passive**만 나간다(`GET /api/recipe-ftp/profiles`).
- **읽기 전용 래퍼** `app/rcp_ftp.py` `ReadOnlyFtp`: `list_dir`(MLSD → 서버가 모르면 `LIST` 파싱, Unix·DOS 형식)·`retrieve`(`RETR`만)·`reconnect`·`close`. 쓰기 명령 메서드 없음, 원시 `ftplib.FTP`는 비공개(테스트로 확인). 파일 한도 초과로 전송을 끊으면 연결을 다시 연다. 오류는 `describe()`가 고정 한국어 문구로 바꾼다(호스트·계정·비밀번호·서버 응답 원문은 어디에도 남기지 않음).
- **수집 `app/rcp_collect.py`**: `recipe_runs` 행 생성 → 접속(수동 모드 기본) → 목록(`layout=folder` 하위 폴더 / `file` 파일) → 이름 필터 → 레시피마다 폴더를 최대 깊이 4까지 훑어 `file_globs`(`/` 없는 패턴은 파일 이름에만, 대소문자 무시)에 맞는 파일을 `.tmp/<run_id>/*.part`로 받으며 sha256 계산 → `blobs/<sha[:2]>/<sha>`로 `os.replace`(이미 있으면 버림) → `add_snapshot`(해시 같으면 `unchanged`). 레시피의 파일이 하나라도 실패하면 그 레시피는 이전 버전을 그대로 두고 오류만 기록(반쪽 스냅샷 없음). 레시피마다 실행 행의 개수를 갱신해 화면이 진행을 폴링한다.
- **missing 표시**: 오류 0건·취소 아님·한도 미도달·목록이 비어 있지 않은 **완전 성공** 실행에서만, 이번에 안 보인 레시피를 `missing=1`로 표시(삭제 안 함). 다시 보이면 해제.
- **상태**: `ok`(오류 0) / `partial`(일부 레시피 성공 + 오류 또는 한도·시간 초과) / `error`(접속·목록 실패 또는 성공 0) / `cancelled`. 앱 시작 시 `running`으로 남은 실행은 `error`("앱이 종료되어…")로 닫는다.
- **API**: `POST/PATCH/DELETE /api/recipe-sources[/{id}]`(DELETE는 DB 행만, 캐시 blob 유지) · `POST /api/recipe-preview/filter`(이름 목록에 필터 적용, 네트워크 없음) · `POST /api/recipe-preview/list`(`rcp_enabled` 필요, 이름만 읽고 받지 않음, 설비에 연결) · `POST /api/recipe-sources/{id}/run`(202, 작업 스레드, `rcp_enabled` 꺼짐 403·꺼진 소스/실행 중 409·프로필 없음 422) · `GET /api/recipe-runs/{id}` · `POST /api/recipe-runs/{id}/cancel`. 한 번에 한 실행(연결 1개)이며 미리보기도 같은 잠금을 쓴다.
- **화면 `#/rcp`**(사이드바 `RCP 관리`): 헤더에 `수집 켜짐/꺼짐` 토글 칩(= `rcp_enabled`, 꺼짐이면 안내 띠와 비활성 버튼), 소스 목록 + 상세(필터 요약, 수집 버튼·취소·편집·지우기, 상태 카드 5칸·오류 목록·이전 실행, 수집한 레시피 표·`누락 N개 보기` 칩·이름 찾기). 편집 창: 프로필·레시피 단위 칩(D-12), 경로·파일 패턴, 규칙 행(종류 칩 4개 + 값 + `제외` 칩), 미리보기 이름 칸(`목록 불러오기`로 채우거나 직접 입력) + 즉시 일치 표시(색 + 아이콘 + 글자).

### 4.6.3 파싱·다시 파싱 (P6-03, D-38)
- **다시 파싱** `app/rcp_parse.py` `reparse_snapshot`: 캐시 blob(`data/recipes/blobs/`, 경로가 blobs 밖이면 거부, sha256 재확인 — 없거나 달라졌으면 그 파일만 오류)을 **현재** 매핑·파서로 다시 읽어 그 스냅샷의 `recipe_params`·파일 `parser/error`·`param_count`·`parse_status`·`parser_info`를 한 트랜잭션으로 바꾼다. 스냅샷 id·내용 해시는 그대로라 **새 버전이 생기지 않는다**. 설비에 연결하지 않으므로 `rcp_enabled`와 무관.
- **낡음 표시**: `GET /api/recipe-snapshots/{id}`의 `parse` = `{stale, mapping, mapping_version, mapping_error, mapping_auto}`. 저장된 `parser_info`의 매핑 이름·버전 또는 파서 버전이 지금과 다르면(또는 파서 도입 전 `unparsed`) `stale`. 자동으로 다시 파싱하지는 않는다(사용자가 `다시 파싱`을 누른다).
- **API**: `GET /api/recipe-mappings`(찾은 매핑 목록: name·vendor·models·mapping_version·description·error) · `POST /api/recipe-snapshots/{id}/reparse`(스냅샷 상세 + `parse`) · `POST /api/recipe-sources/{id}/reparse`(소스 레시피들의 **현재** 스냅샷, 수집 중이면 409, `{snapshots, with_problems}`). `GET /api/recipes` 항목에 `parse_status` 추가.
- **화면**: 레시피 표에 `파싱` 상태 배지 열, 레시피 이름을 누르면 상세 창 — 상태 배지·수집 시각·파일/파라미터 수·버전, 매핑 한 줄(이름·버전·자동 선택 여부)과 낡음/매핑 오류 안내 띠, 확인할 점(경고) 접이식, 파일별 파서·오류, 파일 선택 칩·찾기·`이름 붙은 항목만` 토글 칩, 그룹별 파라미터 표(이름·값·단위·경로, 최대 500행), 바닥 `다시 파싱`. 소스 머리글에 `다시 파싱`(소스 전체), 소스 편집 창에 `설비사 매핑` 칩(자동·찾은 매핑).

### 4.6.4 비교·이력 (P6-04, D-39)
- **원칙**: 읽기 전용·로컬. DB의 파라미터 행(`recipe_params`)만 읽고, `compare`(text/number)·`tolerance`는 **조회할 때마다 매핑 파일에서 읽는다**(DB에 저장 안 함 → 허용오차를 고치면 다시 파싱 없이 바로 반영). 키 = (파일, 경로). 숫자 비교는 `|a-b| <= tolerance`(경계 포함, 부동소수 오차 흡수), 한쪽만 숫자면 `type_changed`(값 종류 바뀜). `nan`·`inf`는 글자로 취급.
- **API**: `GET /api/recipes/{id}/history`(최신순 `items[{id, collected_at, content_hash, parse_status, param_count, file_count, is_current, previous_id, summary{added, removed, changed, type_changed, within_tolerance, files_added/removed/changed}}]`, 첫 수집은 `summary: null`, `limit` 기본 50) · `GET /api/recipes/{id}/diff?a=&b=&only_changes=true`(같은 레시피의 두 스냅샷, a=기준·b=대상, 행 `{file, path, label, unit, group, old, new, status, delta, type_changed, within_tolerance, compare, tolerance}`, 다른 레시피면 422) · `GET /api/recipe-compare?ids=3,5:12`(레시피 2~6개, `id:스냅샷`으로 버전 지정, 기본 현재 스냅샷) → `{columns, rows[{…, values[], marks[], diff}], groups, summary{total, differing, missing}, mapping}`. `marks`: `""` 같음 · `d` 기준(첫 값 있는 열)과 다름 · `m` 그 레시피에 없음. · `GET /api/recipe-compare/export.xlsx?ids=…&only_diff&group&q`(화면 필터 그대로, `app/xlsx.py`, 값은 모두 문자열 → 수식 주입 없음, 판정·다른 열 칸 + 정보 시트).
- **화면**: 레시피 표 `비교` 열의 `담기` 토글 칩(소스를 옮겨도 유지, 최대 6) → 아래 `비교 담기` 막대 → `비교하기` 창: 열 카드(첫 열 `기준`), `다른 것만/전체` 칩 · 그룹 칩 · 찾기 · `복사(TSV)` · `엑셀로 저장`, 그룹 머리글이 있는 **가상 스크롤 표**(보이는 줄만 DOM에 둠, 5천 줄 5ms, ↑↓ PageUp/Down Home/End, `role=grid`·`aria-activedescendant`). 다른 칸은 `≠`, 없는 칸은 `∅ 없음` + 줄무늬로 **색에만 의존하지 않는다**. 레시피 상세의 `변경 이력` 칩: 시간순 타임라인(변경 요약 `추가 2 · 삭제 1 · 변경 3`), `이전 버전과 비교` 또는 `기준`/`대상` 두 개를 골라 `두 버전 비교` → 상태(`＋ 추가`·`－ 삭제`·`≠ 변경`)·이전 값·새 값·증감 표(칩 필터·찾기·TSV).

## 5. 데이터 모델 (SQLite)

공통 컬럼: `id INTEGER PK`, `created_at TEXT`, `updated_at TEXT` (ISO 8601).

### task_fields (P2B-03, 마이그레이션 `002_task_fields.sql` — 4.2.2)
| 컬럼 | 타입 | 설명 |
|---|---|---|
| key | TEXT UNIQUE | 내부 이름(영문, 변경 불가). `tasks.props`의 키 |
| label | TEXT | 화면 이름(변경 가능) |
| type | TEXT | `choice` / `multi` / `text` / `person` / `date` / `number` / `check` |
| options | TEXT(JSON) | 선택지 `[{value,label,color}]` (choice·multi) |
| sort_order | INTEGER | 표시 순서 |
| show_filter / show_row | INTEGER | 필터 줄·행 메타 표시 여부 |
| archived | INTEGER | 1이면 숨김(값은 보존, 새 값 쓰기 거부) |
| builtin | INTEGER | 1이면 기본 제공(priority·requester·due_date·planned_date) |

`tasks`에 `props TEXT NOT NULL DEFAULT '{}'`(JSON)를 추가했다. **호환 방식(P2B-03 확정)**: 기존 `priority`·`requester`·`due_date`·`planned_date` 컬럼은 **지우지 않고** 같은 키의 `props` 값과 함께 쓰는 미러로 유지한다(마이그레이션이 기존 값을 props로 복사). 그래서 기존 SQL·필터·일지 자동 표시·대시보드가 그대로 동작한다. 쓸 때는 둘을 항상 같이 갱신한다.
- 선택지 `{value,label,color?,parent?,archived?}`: `value`는 글자 또는 정수, `parent`는 같은 항목 안의 다른 선택지(계층, 순환 거부). 우선순위의 선택지는 1·2·3 고정(이름·색만 변경).
- 값 검증: choice=선택지 값, multi=선택지 값 목록(중복 제거), text/person=글자, date=YYYY-MM-DD, number=숫자, check=참/거짓.

**API (P2B-03, 모두 `/api/todos` 아래, 오류는 `{"error"}`)**
- `GET /api/todos/fields?include_archived=true` → `{items}`; `POST` `{key,label,type,options?}` → 201 (key 형식 `^[a-z][a-z0-9_]{0,31}$`, 예약어·중복 거부, 중복 409); `GET /fields/{key}` (+`used_by`); `PATCH /fields/{key}` `{label,type,show_filter,show_row,archived,sort_order,options,option_moves}`; `PUT /fields/order` `{keys:[...]}`(전체 key 한 번씩).
- 타입 변경은 기본 항목이거나 값이 있으면 409. 선택지 `＋`: `POST /fields/{key}/options` `{label,color?,parent?}` → 항목 반환.
- 선택지 삭제: `PATCH`의 `options`에서 빼면 된다. 그 선택지를 쓰는 할일이 있으면 409 — `option_moves: {"옛값": "새값" | null}`로 옮기거나 비운다. 위치 규칙이 쓰는 선택지는 409. 지운 선택지의 하위는 한 단계 위로 올라간다.
- 항목 삭제 `DELETE /fields/{key}`: 값이 있거나 기본 항목이면 **보관**(`archived`, 값 보존), 값이 없으면 삭제. `?purge=true`는 정의와 모든 할일 값을 완전 삭제(기본 항목이면 미러 컬럼도 비움, priority는 2). 위치 규칙이 쓰는 항목은 purge 409(`규칙 n번`).
- 할일: 응답에 `props`(객체)가 추가된다. `POST/PATCH`는 `props`(키별 병합, null=제거)를 받는다. 기존 최상위 `priority`·`requester`·`due_date`·`planned_date`도 그대로 받으며 둘이 겹치면 최상위가 이긴다. 정의 없는 키·보관된 항목에 쓰기는 400.
- 필터: 기존 필터는 그대로, 추가로 `?field_<key>=a,b`(한 항목 안에서는 OR, 항목끼리 AND; multi는 하나라도 포함). 없는 항목은 404.
- 위치 규칙: `GET/PUT /api/todos/page-rules` `{rules:[{conditions:[{field,op,value?}],path}]}` → `settings.page_rules`(JSON). op는 `is`·`not`·`set`·`empty`. 저장 시 항목·선택지·템플릿 변수(`{연}` `{월}` `{에픽위치}` 또는 항목 key·이름)가 실제로 있는지 검증한다.

**이슈 페이지·위치 규칙 (P2B-09, 마이그레이션 없음 — `tasks.page_path` 재사용)**
- 페이지 = `note` 폴더 + `_page.json`의 `task_id`(이슈 ID). 자동 폴더는 `auto: true`. `GET /api/pages/tree` 노드에 `task_id`·`auto` 추가. `PATCH /api/pages`로 페이지를 옮기면 `tasks.page_path`가 따라가고 `DELETE`(휴지통)하면 비워진다.
- `POST /api/todos/page-preview` `{task_id, relocate?, override?}` 또는 `{draft:{title,props,planned_date,…}, override?}` → `{folder, by, kind(rule|default|journal|folder), rule, title, page_path, new_folders[], journal}`. 이미 페이지가 있으면 `{exists:true, path}`(`relocate:true`면 `current`와 계획도 함께). 아무것도 쓰지 않는다. override = `{kind:"journal"}` | `{kind:"folder", path}` | 생략/`auto`.
- `POST /api/todos/{id}/page` `{override?}` → `{created, path, page, placement, task}`. 두 번째부터 `created:false`(기존 페이지, 내용·위치 불변). `POST /api/todos/with-page` = `POST /api/todos` 본문 + `override?` → 201 `{created, path, page, placement, task(+journal_days)}`. `POST /api/todos/{id}/page/relocate` `{override?}` → `{moved, path, from?}`(페이지 없으면 409, 자기 하위 400).
- **메모 = 페이지 본문 (P2B-10, D-29)**: 페이지가 있는 이슈의 메모는 그 페이지의 `index.md`와 **같은 글**이다. `GET /api/todos/{id}`는 본문을 `note`로 돌려주고(`memo_merged:true`면 이번에 합쳤다는 뜻), `PATCH {note}`는 본문에 쓴다. `PUT /api/pages`도 연결된 이슈의 `tasks.note`(검색·복사용 거울)를 같이 갱신한다. 페이지가 없으면 `tasks.note`(마크다운 문자열)가 원본. 옛 데이터(P2B-09까지 따로 편집된 메모/본문)는 시작 시·첫 읽기 때 한 번 합쳐 `_page.json`에 `memo_unified`를 찍는다(다르면 본문 뒤에 `## 통합 전 이슈 메모`로 이어 붙이고 원문은 `memo_before_merge`에 보존).
- `POST /api/todos/{id}/files?name=x.png`(원시 바디) → `{file:"files/img-….png", url}`: 페이지가 있으면 페이지 `files/`, 없으면 `vault/.issue-files/<id>/`(페이지 생성 시 `files/`로 이동, 마크다운 참조 `files/…`는 그대로 유효). `GET /api/todos/{id}/file?name=` — 페이지 폴더 → 이슈 폴더 순으로 찾음. 복사(`/api/structure/copy`)는 이미지도 새 이슈 폴더로 복사.
- 이미지 폭(마크다운): `![](files/a.png)` 자동(본문 폭 안, 비율 유지), `{size=small}` 소형 240px, `{width=480}` 고정 px(60~2400, 본문 폭 초과 시 본문 폭으로 제한), `{size=orig}` 원본 해상도. 접힘은 파일에 쓰지 않고 `settings.memo_folds`(`t:<이슈id>` 또는 `p:<경로>` → 제목 키 배열)에 둔다.
- `GET/PUT /api/todos/page-rules` 응답·본문에 `fallback`(`journal`·`type`·`inbox`) 추가. PUT은 규칙·기본값을 모두 검증한 뒤에 저장한다. `POST /api/todos/page-rules/overview` `{rules?, fallback?}` → `{rules:[{index, matches, example:{id,title,folder}}], pages:[{task_id, title, path, folder, rule_folder, by, differs}], fallback, fallbacks}` (저장하지 않은 초안도 계산).
- 템플릿: `{연}{월}`은 하기로 한 날(없으면 생성일), `{에픽위치}`는 에픽 이름과 같은 제목의 첫 페이지 경로(없으면 `미분류`) `[가정]`, 항목 값은 계층이면 경로(`HBM/HBM-A`), 없으면 `미분류`. 값 안의 금지 문자는 제거. 기본 위치: 일지 `일지/{연}/{연}-{월}`, 유형별 `MI 공정업무/{유형}`, 할일 폴더 `MI 공정업무/할일`(최상위 7번째 트리를 만들지 않으려 SPEC 초안 `할일`에서 변경).
- 화면: 이슈 상세의 '페이지' 행(확장/열기/위치 변경), 할일 화면 '할일 페이지 추가'(Alt+N, Ctrl+N), 구조 › '페이지 위치 규칙' 탭(조건 칩 편집, 순서 ↑↓, 변수 칩, 해당 이슈 수·예시, 기본 위치 칩, 페이지별 현재 위치 vs 규칙 위치와 '옮기기').

**구조 보기·분류 관리 (P2B-07, 마이그레이션 `004_structure_defaults.sql`)**
- 004: 기본 분류 `epic`(에픽)·`type`(유형)을 일반 `choice` 항목(builtin=0)으로 시드 — 이름 변경·보관·삭제 가능. 초기 보기는 에픽 → 유형 → 이슈.
- 보기 설정은 `settings.structure_view`(JSON `{mode:"fields"|"free", levels:[key…], styles:{key:{icon,color}}}`)에 저장되고 재시작 후 복원된다. 이슈의 분류 값(`tasks.props`)과 완전히 별개다. 계층 후보는 단일값 항목(`choice`·`person`, 보관 안 됨)뿐.
- `GET /api/structure/view` → `{mode, levels:[{key,label,icon,color}], available:[…], free_reason, saved, icons, colors}`. 저장된 계층에 삭제·보관된 분류가 있으면 **규칙이 깨진 것**으로 보고 `mode:"free"` + `free_reason`을 돌려준다(저장 값은 보존).
- `PUT /api/structure/view` `{mode, levels:[key | "new:<tmp>"], new_fields:[{tmp,label}], styles}` — 전부 검증한 뒤 새 분류(`c1`, `c2`… choice 항목)를 만들고 설정을 한 번에 저장(적용 = 원자적, 취소 = 서버 호출 없음). 오류: 중복·예약 이름 409/400, 계층 8단계 초과, 알 수 없는 아이콘·색(`layers grid box person flag ring` × `violet mint blue peach pink yellow`).
- `GET /api/structure/classes` → 분류별 `{used_by, rules[], in_view, archived, builtin, groupable}`; `GET /api/structure/classes/{key}/impact` → `{used_by, total_tasks, options:[{value,label,count,rules[]}], rules[], in_view}`. 삭제·보관·선택지 이동은 기존 `/api/todos/fields` API(`DELETE`, `?purge=true`, `PATCH option_moves`)를 그대로 쓴다.

**구조 작업표·자유 배치·복사 (P2B-08, 마이그레이션 `005_structure_free.sql`)**
- 자유 배치 위치는 `structure_nodes`(id, parent_id, label, field_key?, field_value?, position)와 `structure_items`(task_id, node_id, position)에만 저장한다. vault 페이지 트리와 별개. 그룹은 선택적으로 분류 값에 묶이며(`field_key/field_value`), 그 아래에 놓인 이슈는 그 값을 받는다. 처음 열 때 현재 계층(`structure_view.levels`)을 그룹으로 한 번 복제하고(`settings.structure_free_seeded`) 이후 편집은 유지한다.
- `GET /api/structure/free` → `{nodes:[…], items:[{task_id,node_id,position}]}` (배치 안 된 이슈는 최상위 끝).
- `POST /api/structure/free/move` `{kind:"group"|"issue", id, parent_id|null, before?:{kind,id}}` → `{free, changed:[task_id…]}`. 그룹은 하위와 함께 이동하고 자기 하위로 옮기면 400 `순환`. 옮긴 이슈(그룹이면 하위 이슈 전체)는 새 경로의 분류 값을 받는다. 이슈 ID 불변. 분류 보기에서의 이동은 `PATCH /api/todos/{id}`의 `props`.
- `POST /api/structure/free/groups` `{label, parent_id|null}` → `free` (분류 값에 묶이지 않은 그룹).
- `POST /api/structure/copy` — `{kind:"issue", task_id}`(제목 + " · 복사본"), `{kind:"group", field_key, value, task_ids}`(분류 보기: choice 분류의 새 선택지 "X · 복사본"을 만들고 그 값으로 복사. `field_key:"epic"`이면 다른 유형 가지의 같은 에픽 이슈 전부 포함), `{kind:"node", node_id}`(자유 배치: 선택한 하위 트리만, 바인딩된 그룹은 새 선택지). 응답 `{created:[새 id…], map, option?, node_id?, free?}`. 복사본은 새 ID이며 상태·메모·props는 값 복사(원본과 독립). 계획일·페이지·평가 연결은 복사하지 않는다.
- `POST /api/structure/delete-preview` · `POST /api/structure/delete` `{items:[{kind:"issue"|"group", id}], children:"move_up"|"delete"}` — 소프트 삭제(V-004, D-40, 마이그레이션 `012_structure_trash`). 미리보기는 `{issues, groups, children, moved_up, moved_groups, pages, journal_lines, subtasks, group_labels, issue_titles, needs_confirm}`; 삭제는 `{trash_id, summary, issues, groups, impact, journal_days, free}`. 한 요청 = 한 트랜잭션(실패하면 DB·휴지통으로 옮긴 페이지 모두 원복), 최대 500개. 그룹은 `children:"move_up"`이면 하위를 그 자리로 올리고 `"delete"`이면 하위 전체를 삭제. 이슈 페이지·이미지 폴더는 `vault/.trash`로.
- `POST /api/structure/trash/{id}/restore` → `{trash_id, summary, issues, groups, journal_days, journal_skipped, free}` — 같은 ID·값·순서·그룹 소속·페이지 연결로 복원. 이미 복원했으면 409, 같은 번호 이슈·그룹이 이미 있으면 409(변경 없음). `GET /api/structure/trash` → `{items:[{id, summary, created_at, restored_at}]}`.

저장소 `app/repositories/recipes.py`: `create_source`(검증)·`list_sources`·`get_source`·`list_recipes`·`get_recipe`·`get_snapshot`·`list_runs`·`upsert_recipe`·`add_snapshot`(해시 같으면 만들지 않음)·`content_hash`·`validate_filter`·`name_matches`. 쓰기 감사 로그 테이블은 P6-05가 새 마이그레이션으로 추가.

### settings
`key TEXT PK, value TEXT` — 일지 자동 표시 on/off, 경고 배수, 백업 폴더, 레시피 쓰기 허용 등.
RCP 플래그(P6-01): `rcp_enabled`(`off`|`on`, 기본 off), `rcp_write_enabled`(`off`|`on`, 기본 off — `rcp_enabled=on`일 때만 켤 수 있고 `rcp_enabled`를 끄면 같이 꺼짐; P6-05 전까지 효과 없음).

## 9. 비기능 요구
- 오프라인 동작 (외부 요청 0건). HTML 페이지의 외부 요청은 경고. 예외: 회사에서 설정한 사내 LLM 주소, 레시피 FTP.
- **사외 반출 금지 (D-17)**: 회사 데이터(vault, DB, 레시피, DOI 이미지)는 집으로 가져오지 않는다. 집에서는 가짜 데이터로 개발, 실제 데이터 작업과 회사 전용 스킬은 회사에서.
- 브라우저: **Chromium 계열**(Edge 우선, Chrome, 네이버 웨일) 최신 버전 (D-16).
- 시작 5초 이내, 페이지 열기 300ms 이내, 현황판 5,000칸 렌더 1초 이내 `[가정]`.
- 백업: 하루 1회 `data/` + `vault/`를 `backups/`에 zip, 30개 보관.
- 삭제는 휴지통(`vault/.trash/`) 경유.
- 회사 이식: `install.bat` 한 번 → `run.bat`. 패키지는 사내 프록시 경유 pip 설치(프록시 주소는 설정으로 입력), 막힌 패키지만 wheel 파일로.
