# DECISIONS — 결정 기록

> 상태: `확정` / `잠정`(확인 필요) / `폐기`. 바꿀 때는 지우지 말고 상태와 이유를 갱신한다.

## 결정

### D-01 기술 스택 — 확정 (2026-11-24)
Python 3.11+ / FastAPI / uvicorn / sqlite3 + 빌드 없는 vanilla JS. 월간 일지는 내장 그리드를 사용한다.
- 이유: 회사 PC에서 Node 빌드 체인 없이 돌아가고, 사용자가 Python을 이미 씀. FastAPI는 AI 모델들이 안정적으로 다루는 스택.
- 2026-11-24: 회사 PC에 Python 있음, pip은 사내 프록시 경유로 대부분 가능 → `install.bat`이 프록시 설정을 받아 설치. 막힌 패키지만 wheel로.
- 추가 예정 패키지(모두 순수 Python 또는 공식 wheel 제공): openpyxl(엑셀 가져오기·내보내기), python-pptx(DOI PPT 가져오기).
- 노트 편집기와 P3-06의 GFM 표는 D-20에 따라 브라우저 기본 기능을 사용한다. P1-05에서는 가짜 시드와 로컬 자산을 확인했다. 이후 다른 화면에 라이브러리가 필요하면 해당 작업에서 채택을 검토한다.

### D-02 앱 형태: 로컬 웹앱 — 확정
로컬 서버(127.0.0.1) + 브라우저 UI. Electron/Tauri는 쓰지 않는다.

### D-03 저장소: 파일(vault) + SQLite — 확정 (2026-11-24 변경)
- **노트·일지·HTML 페이지 → `vault/` 폴더의 일반 파일** (.md / .html)
- **할일·평가·MOS·레시피 같은 정형 데이터 → `data/mi_planner.db`**
- 이유: 사내 LLM 에이전트가 앱 없이도 노트를 파일처럼 바로 읽고 쓸 수 있고, 연도별로 폴더째 떼어 보관하기 쉽다(원노트 "파일 분리" 대체). 정형 데이터는 정렬·집계가 필요해 DB.
- 이전: "SQLite 단일 파일"(v0.1) → 폐기.

### D-04 오프라인 우선 — 확정
CDN 금지, 프론트 라이브러리는 `web/vendor/`, Python 패키지는 회사 이식 시 `vendor/wheels/`.

### D-05 에이전트 규칙 단일 원천 — 확정
규칙은 `AGENTS.md`에만. `CLAUDE.md`는 `@AGENTS.md`로 불러온다.

### D-06 진행 관리: project_flow.html — 확정
`FLOW` 데이터가 원본, 에이전트가 `done: true`로 갱신. 2026-11-24 단계 재편으로 브라우저 저장 키를 `mi_planner_flow_v2`로 바꿈(옛 체크와 섞이지 않게).

### D-07 모델 역할 분담 — 확정
설계·큰 판단은 Opus(채팅), 구현은 Claude Code Sonnet, 디버깅·테스트·반복은 Codex.

### D-08 페이지 = 폴더 (folder-note) — 확정
페이지 하나 = 폴더 하나(`_page.json` + `index.md` 또는 `index.html`). 하위 페이지 = 하위 폴더.
- 이유: 컨플루언스식 계층. 옵시디언에서 "폴더 자체에 노트를 못 단다"는 불만을 구조적으로 없앤다.
- 페이지 종류: `note` / `html` / `journal` / `board` / `table`.

### D-09 대기 관리 = 평가 단계 이력 — 확정
v0.1의 `queue_items`(검사·Review 대기 별도 관리)를 폐기. 평가 현황판 칸의 **단계 전환 이력**(`eval_stage_log`)으로 대기 시간을 계산한다.
- 단계는 평가마다 편집 가능. 마스터: 검사대기 → 검사완료 → 리뷰대기 → 리뷰완료&분류대기 → 분류완료 → 정리완료.
- 칸에는 단계 외에 값 항목(숫자·텍스트·OK/NG·체크)도 입력.

### D-10 LLM 연동 2단계 — 확정
1단계: 파일 + `skills/` + 에이전트용 CLI + "AI에게 요청" 복사 버튼 (사내 OpenCode / Claude Code / Codex 공통).
2단계: 사내 LLM API 직접 호출(앱 내 채팅). Python 호출 가능 확인(2026-11-24), 인증은 사내 프록시가 처리. 주소·키·모델은 `config/local.json`(git 제외), 호출은 `app/llm.py` 한 곳.
- 논문·특허 작성, PPT, 강의 HTML 같은 **생성 작업은 앱 기능이 아니라 스킬**로 만든다. 앱을 작게 유지.

### D-11 RCP 관리: 읽기 전용 우선 — 확정
수집·파싱·비교·이력까지 먼저. 수정·업로드는 P6 마지막에 **자동 백업 + diff 미리보기 + 명시적 확인 + 로그**를 갖춘 뒤, 설정에서 켤 때만.

### D-12 UI: 드롭다운 대신 버튼 — 확정
필터·보기 전환·상태 변경은 토글 칩/버튼으로. 선택지가 10개를 넘을 때만 검색 가능한 목록.

### D-13 일지 자동 표시는 옵션 — 확정
납기 할일·밀린 평가 단계를 일지 칸에 읽기 전용으로 표시. 설정에서 끄고 켬. 파일에는 쓰지 않는다.

### D-14 노트 배치: 단(column) 구조 — 확정
원노트식 완전 자유 배치 대신 컨플루언스식 단 추가 + 열 너비 조절 + 스크롤/맞춤 모드. 수평 배치는 되지만 정리는 유지.

### D-15 서식: 원노트 수준 텍스트 서식 — 확정
글자 크기·굵게·기울임·밑줄·취소선·형광펜·글자색을 위지윅 편집기로. 저장은 마크다운 + 허용 목록 인라인 HTML(`<u>`, `<mark>`, `<span style=color/font-size>`), 크기·색은 프리셋.
- 이유: 원노트의 가장 좋았던 점 중 하나. 허용 목록·프리셋으로 제한해야 파일이 깨끗하고 LLM이 읽기 쉽다.
- P3-01에서 왕복(편집→저장→열기) 보존 검증. 실패 시 note 본문을 정제된 HTML로 저장하는 쪽으로 변경.

### D-16 대상 브라우저: Chromium 계열 — 확정
Edge(회사 메인), Chrome, 네이버 웨일. Firefox·Safari는 고려하지 않는다 → 최신 CSS/JS 기능을 폴리필 없이 사용.

### D-17 사외 반출 금지 — 확정
회사 데이터는 집으로 가져오지 않는다. 집 = 가짜 데이터로 기능 개발, 회사 = 실제 데이터·회사 전용 스킬(PPT 템플릿, 레시피 파서, dcoll)·원노트 이관. 코드만 회사로 옮긴다.

### D-18 DOI = 이미지 중심 라이브러리 + 공유 패키지 — 확정
DOI는 표가 아니라 이미지 카드 + 표 겸용. 기존 PPT에서 가져오기 지원. 다른 사람·부서와는 폴더 패키지(이미지 + doi.json)를 사내 드라이브로 주고받는다. 가져온 항목은 출처 표시·읽기 전용.

### D-19 레시피 파싱: 범용 파서 + 설비사 매핑 파일 — 확정
XML/INI/TXT 범용 파서를 내장하고, 설비사별 차이는 `parsers/<vendor>.json` 매핑으로 흡수. 코드 파서는 범용으로 안 될 때만.

### D-20 노트 편집기: 직접 만든 contenteditable 편집기 (외부 라이브러리 없음) — 확정 (P3-01, 2026-11-24)
브라우저 기본 위지윅(`contenteditable`)에 마크다운 변환기(`web/js/mdconv.js`)를 직접 붙인다. Tiptap·Quill 등 후보는 쓰지 않는다.
- 이유: 빌드 도구 없이 vendor 해야 하고(보안망·외부 다운로드 불가), 저장 형식이 D-15의 "마크다운 + 허용 목록 HTML"이라 라이브러리 내부 모델이 오히려 변환 부담. 변환기를 직접 가지면 허용 목록·프리셋 제거 규칙을 한곳에서 통제한다.
- 검증(D-15 왕복): `web/test/mdconv.html`에서 제목·굵게·기울임·취소선·코드·밑줄·형광펜·색/크기·목록·체크리스트·이미지·이스케이프가 편집→저장→열기→저장에서 변하지 않음(11/11 PASS). 허용 밖 태그·스타일·프리셋 밖 값은 저장 때 제거, 읽을 때 원시 HTML은 텍스트로만 표시.
- 한계(알고 감수): 중첩 목록은 평탄화, 링크는 일반 텍스트, 붙여넣기는 서식 없는 텍스트만, 문단 사이 빈 줄은 저장 시 1개로 정리. 에디터가 `execCommand`(비권장이나 Chromium 지원 유지, D-16)에 의존 — 사라지면 이 모듈만 교체.
- 이 결정은 Opus 작업이었으나 Sonnet 세션에서 진행함. 검토 후 바꿀 점이 있으면 알려 주세요.
- 표·단(columns)은 이 편집기 위에 P3-03/P3-06에서 블록으로 추가.
- **재검토 (2026-11-24, P3-01 재수행 · Final 디자인·P2B 편집기 기준) — 결정 유지, 단 변환기 보강 필수.**
  - 유지 이유: 라이브러리 없이 동작(`web/vendor/` 자체가 없음, 외부 URL 0 — P2B-06 테스트), 인라인 서식 왕복 무손실(`web/test/mdconv.html` 12/12, 한글·밑줄·형광펜·색/크기·이미지 폭 `{width=N}` 포함), 페이지·이슈 메모가 이미 같은 `mountEditor`를 씀(D-29). Tiptap 등으로 바꿔도 아래 결함은 그대로 변환기 문제라 교체 이득이 없다. D-15의 "정제 HTML 저장" 대안은 발동하지 않는다(실패는 블록 수준이며 변환기에서 고칠 수 있음).
  - 증거(브라우저에서 `mdconv` 직접 호출, 편집→저장→열기→저장): 안정(2회차 동일)은 전부 OK. **원문과 달라지는 것 3가지**: ① 중첩 목록 `- 상위\n  - 하위` → 평탄화 + 빈 줄 삽입, ② 별표 표시 `- [*] …` → `- [\*] …`(D-21 표시 깨짐; `[!]`는 우연히 보존되나 불렛 글자로 표시), ③ 코드 펜스 ` ``` ` → `` \`\`\` `` 이스케이프. contenteditable에서 제목에 한 단어만 입력해도 `save`가 본문 전체를 다시 써서 ①~③이 파일에 반영됨(열기만 하면 쓰지 않음 — `last` 비교). 표(`| A | B |`)·`[[링크]]`·`> 인용`·`####`·` → 할일 #12`는 텍스트로 원문 보존(표는 문단 `<br>`로만 보임).
  - Final 디자인과의 차이: DESIGN "공통 줄 편집기"·D-21은 노트 본문에도 Tab/Shift+Tab 들여쓰기, `Ctrl+.` 불렛, `Ctrl+1` 표시 순환, Alt+↑↓ 블록 이동, 하위 줄 접기를 요구하나 `note.js`는 Tab을 막고(`nested lists are not supported yet`) 표시 순환이 없다. IME는 `e.isComposing`만 검사(일지 편집기는 `keyCode === 229`도 검사).
  - **후속 작업이 지켜야 할 제약** (P3-02R·P3-03·P3-05·P3-06·P3-08):
    1. 저장 형식은 일지와 같은 줄 모델: 들여쓰기 2칸(`lineeditor-core.js` `STEP`), 표시 `- [ ]`/`[x]`/`[*]`/`[!]`, 형광펜 `<mark>`. 노트 변환기는 이 다섯 표시와 중첩을 무손실 왕복해야 한다.
    2. 변환기가 모르는 블록(코드 펜스, 표, 인용, `####` 이하, HTML 주석, 앞으로 추가될 블록)은 **원문 그대로 통과**시키고 편집 불가 블록으로 보여 준다. 사용자가 고치지 않은 블록은 저장 때 한 글자도 바뀌면 안 된다(사람·LLM이 쓴 파일 보호).
    3. 단(P3-03): 단 경계는 `index.md` 안의 블록 표식 한 줄(권장 `<!-- column -->`, 너비 비율은 `_page.json`)로 두고 변환기 왕복 케이스를 `web/test/mdconv.html`에 추가. 단이 없는 파일은 지금과 동일해야 한다.
    4. 표(P3-06): 테스트를 통해 내장 HTML 표와 셀 입력으로 편집·정렬·Excel TSV 교환을 구현했다. GFM 마크다운 원문을 보존하고 로컬 브라우저 기능만 사용한다. Tabulator 도입은 별도의 정보 표 기능에서 필요할 때 재검토한다.
    5. 제목 접기(P3-05)는 이미 `settings.memo_folds`로 구현됨(D-29) — 파일에 쓰지 않는 원칙 유지, 새로 만들지 말고 확인·마감만.
    6. `[[링크]]`(P3-08)는 지금처럼 텍스트로 보존되어야 하며, 링크 표시는 읽기 렌더 단계에서만 꾸민다(저장 문자열 불변).
    7. 한글 IME: 편집기 keydown은 `e.isComposing || e.keyCode === 229`면 무시. 실제 Edge IME 확인은 회사 점검표(6장)로.
    8. 모든 변환기 변경은 `web/test/mdconv.html`에 "원문 = 1회 저장 = 2회 저장" 케이스로 남긴다.

### D-21 줄 편집: 불렛·들여쓰기·Ctrl+1 표시 순환 — 확정 (2026-11-24, 사용자 피드백)
일지 칸(과 이후 노트)에서 `Ctrl+.` 불렛, `Tab`/`Shift+Tab` 들여쓰기, `Ctrl+1`로 줄 표시를 `없음→☐→☑→★→!` 순환. 저장은 `- [ ]` `- [x]` `- [*]` `- [!]`.
- 이유: 원노트에서 실제로 가장 많이 쓰던 입력 방식인데 SPEC에 빠져 있었음. 앱의 1순위 입력 경로.
- 순환 순서·Alt+↑↓·하위 불렛→하위 할일 승격은 `[가정]`. `Ctrl+1`이 브라우저 탭 전환과 겹치면 `Ctrl+Alt+1`로 대체(실측 후 기록).
- 상세: SPEC 4.2.1.
- **구현 (P2B-02)**: `web/js/lineeditor.js` + `lineeditor-core.js`. `Ctrl+1`·`Alt+1`·`Ctrl+Alt+1` 세 가지 모두 표시 순환으로 받는다(브라우저가 가로채는 키는 도움말의 '키 확인'으로 사용자가 직접 확인). 형광펜 `Ctrl+Alt+H`/`Alt+Shift+H`, 별표 `Ctrl+Alt+S`/`Alt+Shift+S`. Tab·Shift+Tab·Enter·Backspace는 단축키 토글과 무관하게 항상 동작. 단축키 토글은 브라우저별 `localStorage`(`mi.editorKeys`). 형광펜 저장은 `<mark>…</mark>`.

- **노트·이슈 메모 (P3-02R)**: 표시 순환은 Ctrl+1·Alt+1. Ctrl+Alt+1은 Final 시안의 제목 1 단축키로 유지한다. 다른 블록 편집 시 읽기 전용 블록과 기존 구분 줄바꿈을 보존한다.

### D-22 할일 항목은 사용자 정의 (고정 컬럼 폐기) — 확정 (2026-11-24)
우선순위·요청자·제품 등은 고정 컬럼이 아니라 `task_fields`(항목 정의) + `tasks.props`(값 JSON). 선택지는 입력하며 추가, 필터·행 메타는 정의에서 자동 생성. 텍스트 `키:값` 토큰으로도 입력 가능.
- 이유: 보고 싶은 항목이 그때그때 바뀐다. P2-03의 `priority`·`requester` 컬럼은 그걸 못 해서 마이그레이션 필요(P2B에서 호환 방식 확정).

### D-26 구조 보기 제외와 분류 삭제는 다른 동작 — 확정 (P2B-07, 2026-11-24)

- 기본 분류 `epic`·`type`은 마이그레이션 004가 일반 항목으로 시드한다. 새 패키지 없음.

### D-27 구조 작업표: 자유 배치 위치는 별도 테이블, 복사는 값 복사 — 확정 (P2B-08, 2026-11-24)

### D-28 이슈 페이지는 선택, 신원은 `task_id`, 배치는 첫 일치 규칙 → 기본 — 확정 (P2B-09, 2026-11-24)
이슈 추가는 `tasks` 행만 만든다. 페이지는 "페이지로 확장"(기존 이슈, 한 번) 또는 "할일 페이지 추가"(이슈+페이지 동시)로만 생긴다. 페이지는 일반 `note` 폴더이고 `_page.json`에 `task_id`가 들어가며(= 이슈 ID와 같은 신원), `tasks.page_path`는 위치 캐시다. 캐시가 어긋나도 `task_id`로 찾아 복구하므로 두 번째 확장은 새 페이지를 만들지 않고 기존 페이지를 연다.
- 위치: 위에서부터 **첫 일치 규칙**(조건 전부 AND, 조건 없는 규칙은 적용 안 됨) → 기본 위치(일지 아래 / 유형별 / 할일 폴더, `settings.page_fallback`). 생성 전 미리보기에서 **일지 아래** 또는 **지정 폴더**로 덮어쓸 수 있다. 없는 폴더는 `auto: true` 폴더로 자동 생성(일지 월은 실제 월 페이지). 이후 분류가 바뀌어도 파일은 **자동 이동하지 않으며**, 명시적 "위치 변경"(relocate)만 옮긴다.
- 전부 아니면 전무: 확장·동시 생성·이동은 SQLite 쓰기 트랜잭션(`BEGIN IMMEDIATE`)을 잡은 채 vault를 만지고, 실패하면 이번 작업이 만든 폴더·페이지만 롤백한다(이동은 원위치+원래 meta 복원). 롤백 대상은 같은 작업이 방금 만든 항목뿐이라 `.trash`를 쓰지 않는다(사용자 데이터 삭제 아님). 동시 생성 중 이슈 생성 후 페이지 실패 시 이슈도 삭제한다.
- 페이지 본문과 이슈 메모는 P2B-10에서 한 글로 통합됨(D-29). 트리에서 페이지를 옮기면 이슈 링크가 따라가고, 휴지통으로 보내면 링크가 풀린다. 새 패키지 없음.

### D-29 이슈 메모와 이슈 페이지 본문은 한 글 — 확정 (P2B-10, 2026-11-24)
페이지가 있는 이슈는 페이지 `index.md`가 **유일한 원본**이고 `tasks.note`는 검색·복사·목록용 거울이다(읽을 때·쓸 때 서버가 맞춘다; 앱 밖에서 파일을 고쳐도 다음 읽기에서 파일이 이긴다). 상세 패널 메모와 페이지는 같은 P3 편집기(`web/js/note.js` `mountEditor`)를 쓴다.
- **기존 어긋난 데이터**: 서버 시작 시와 첫 읽기(이슈 GET·페이지 GET) 때 한 번 병합한다. 한쪽이 비었거나 메모가 본문에 이미 들어 있으면 그대로, 둘이 다르면 본문 뒤에 `## 통합 전 이슈 메모` 아래로 메모를 이어 붙이고 원문을 `_page.json.memo_before_merge`에 남긴다(어느 쪽도 버리지 않음). 병합 뒤 `_page.json.memo_unified`로 다시 하지 않는다. 읽기 전에 쓰기가 오면 쓰기 직전에 같은 병합을 먼저 한다.
- **이미지**: 마크다운에 `![](files/x.png){size=small|orig}` / `{width=N}`(자동은 접미사 없음). 페이지 없는 이슈의 이미지는 `vault/.issue-files/<id>/`에 두고 페이지가 생기면 `files/`로 옮긴다(참조 문자열 불변). 접힘은 파일이 아니라 `settings.memo_folds`.
- 알고 감수: 페이지를 휴지통으로 보내면 메모 텍스트는 거울(`tasks.note`)에 남지만 그 페이지의 이미지는 휴지통 폴더에 있다. 이슈를 지워도 `.issue-files/<id>`는 남는다. 새 패키지 없음.

### D-40 구조 화면 삭제는 소프트 삭제 + 스냅샷 복원, 그룹 삭제는 하위를 위로 (V-004, 2026-11-24)
이슈·자유 배치 그룹 삭제는 `POST /api/structure/delete` 한 번이 한 트랜잭션이며 `structure_trash`(마이그레이션 012)에 JSON 스냅샷(이슈 행·그룹 행·이전 형제 순서·페이지/일지 줄 기록)을 남긴다. `tasks`에 삭제 열을 두지 않은 것은 모든 조회가 삭제 상태를 알아야 하는 위험을 피하려는 것이다. 이슈 페이지(와 남은 이미지 폴더)는 기존 휴지통(`vault/.trash`)으로 가고, 복원은 원래 위치(부모가 없으면 최상위, 같은 이름이면 ` (2)`)로 되돌린다. 일지 연결은 기존 이슈 삭제처럼 연결만 풀고(줄 내용 유지), 복원은 줄이 그대로일 때만 다시 건다(바뀐 줄은 건너뛰고 알림). 그룹 삭제의 기본은 **하위를 지우지 않고 그 자리로 한 단계 올림**(`children: "move_up"`), `"delete"`는 하위 이슈·그룹까지 삭제. 복원은 같은 ID로 되살리며 중간에 다른 곳으로 옮겨진 하위는 되돌리지 않고, 그 사이 새로 생긴 항목은 그대로 둔다. 같은 번호 이슈가 이미 있으면 409로 아무것도 바꾸지 않는다. 분류 기준 보기의 그룹은 분류 값이라 여기서 지우지 않는다(분류 관리, D-26). 되돌리기 스택은 브라우저 세션(탭) 안에서만 기억하고 서버 기록은 자동으로 지우지 않는다. 새 패키지 없음.

### D-39 비교 규칙은 조회 시점에 매핑에서, 첫 열이 기준, 목록은 가상 스크롤 (P6-04, 2026-11-24)
새 패키지·마이그레이션 없음. 상세는 SPEC 4.6.4.
- **compare/tolerance는 DB에 두지 않는다**: 매핑 파일을 고치면 다시 파싱 없이 diff·비교에 바로 반영된다(D-38의 "다시 파싱"은 이름·그룹·값 추출에만 필요). 매핑이 깨졌으면 규칙 없이 글자 그대로 비교하고 화면에 알린다.
- **여러 레시피 비교의 기준은 첫 열**: 허용오차는 이행적이지 않아(1.00·1.04·1.08, 허용 0.05) 쌍별 비교는 모호하다. "기준과 다른가"로 정의해 항상 같은 답이 나온다. 기준 열에 없는 항목은 첫 값이 있는 열이 기준.
- **같은 레시피의 두 버전은 이력에서, 서로 다른 레시피는 비교에서**: 같은 레시피를 비교 열에 두 번 넣을 수 없다.
- **5천 줄 표는 가상 스크롤**(고정 줄 높이, 보이는 줄 + 여유 8줄만 DOM). 필터·검색은 화면(JS)에서, 내보내기는 같은 필터를 서버에서 다시 적용한다.
- **차이 표시는 색 + 기호 + 글자**(`≠`·`∅ 없음`·`＋ －`), 줄무늬 배경. 엑셀은 모든 값을 문자열로 써서(`001` 보존, `=…` 수식 주입 차단) 판정 열로 차이를 표시한다.

### D-38 범용 파서는 표준 라이브러리로 직접, 파싱 실패는 수집을 멈추지 않고, 다시 파싱은 제자리 갱신 (P6-03, 2026-11-24)
새 패키지·마이그레이션 없음(`xml.etree`·`re`·`fnmatch`·`json`). 상세는 SPEC 4.6.1 5)·6), 4.6.3.
- **INI·TXT는 configparser 대신 직접 읽는다**: 설비 파일은 중복 키·키만 있는 줄·이상한 주석이 흔하고, P6-05 바이트 단위 수정을 위해 **줄 번호**가 필요하다(configparser는 줄 번호를 주지 않고 중복 키·형식 오류에서 예외). 중복은 `키[2]`로 구분해 보존한다.
- **XML 안전**: `<!DOCTYPE`·`<!ENTITY`는 전체 거부(엔티티 폭탄·XXE를 파서에 닿기 전에 차단, pptx/xlsx와 같은 원칙이되 검사 범위는 앞 4KB가 아니라 전체), 깊이·요소 수 한도. 디코딩을 우리가 하고(cp949 등 expat이 모르는 선언 대응) 선언의 `encoding=`은 제거한다. 루트 요소 이름은 경로에서 뺀다(벤더 공통 래퍼일 때가 많고 `Header/*` 같은 무시 규칙이 짧아짐; 같은 이름 형제의 첫째에는 번호를 붙이지 않아 항목이 추가돼도 기존 경로가 바뀌지 않음).
- **옵션은 매핑 파일에**: `files[].options`(`key_attr`, txt `mode` 등)로 코드 파서 없이 흔한 변형을 흡수한다(D-19의 "코드 파서는 범용으로 안 될 때만"). 파서가 옵션을 검증하고 틀리면 그 파일의 한국어 오류가 된다.
- **파싱 실패는 수집을 멈추지 않는다**: 원본은 항상 캐시·스냅샷에 남고 파일 `error`·스냅샷 `parse_status`로 표시한다. 예상 못 한 예외는 고정 문구만 저장(내부 경로·내용 비노출). 변화 없는 레시피는 다시 파싱하지 않아 반복 수집이 가볍다.
- **다시 파싱 = 제자리 갱신**: 매핑·파서 버전이 바뀌면 `낡음`으로 알리고(자동 실행 없음) 사용자가 누르면 같은 스냅샷의 파라미터만 새로 만든다. 내용 해시가 그대로라 이력이 늘지 않는다. blob이 없거나 해시가 달라졌으면 그 파일만 오류로 기록(경로 이탈도 거부).
- **매핑 자동 선택**: 소스에 매핑 이름이 없으면 설비사·모델이 같은 매핑을 찾는다(소스 편집 창의 `자동` 칩). 매핑 파일이 깨졌으면 매핑 없이 읽고 알린다.

### D-37 수집은 작업 스레드 + DB 행 폴링, 완전 성공에서만 missing 표시 (P6-02, 2026-11-24)

- **missing 보호**: 부분 실패·취소·한도 도달·빈 목록(서버 일시 오류로 목록이 비는 경우)에서는 표시하지 않는다. 필터를 좁히면 범위 밖이 된 레시피도 `missing`이 된다(삭제 아님, 다시 넓히면 해제).

### D-36 RCP 관리 설계: 프로필 이름만 DB에, 내용 해시 스냅샷, 정규식 없는 필터, 두 열쇠 쓰기 (P6-01, 2026-11-24)
새 패키지 없음(`ftplib`·`hashlib`·`fnmatch`·`json`). 상세는 SPEC 4.6.1.
- **접속 정보**: FTP 주소·계정은 `config/local.json`의 `recipe_ftp.profiles`(git 제외)에만, DB 소스는 프로필 이름만. 비밀번호는 환경 변수 우선.

- **스냅샷**: 레시피 버전 = 파일들의 (경로, sha256) 해시. 현재와 같으면 새로 만들지 않고, 되돌림도 새 버전. 파서·매핑 버전이 바뀌면 blob에서 다시 파싱(새 스냅샷 아님).

- **파서·매핑**: `parsers/base.py` 레지스트리 + 순수 파서. 매핑은 버전 있는 JSON(`format_version`, `mapping_version`). 실제 회사 매핑은 `config/recipe_mappings/`(git 제외, D-17), 커밋되는 `parsers/mappings/`에는 가짜 예시만.
- **쓰기(P6-05)**: 설정 `rcp_write_enabled` + 프로필 `allow_write` 두 열쇠, 기본 dry run, 기준 해시 재확인, 백업 검증, diff 미리보기, 이름 입력 확인, 업로드 후 해시 검증·자동 복구, 추가만 되는 감사 로그(DB + jsonl). 파일 1개 단위, CLI·스킬에는 쓰기 없음.

### D-35 DOI 공유 패키지는 zip 한 개(manifest.json + images/)로 주고받는다 (P5-04, 2026-11-24)
새 패키지 없음(`zipfile`·`json`·`hashlib`만). SPEC의 "폴더(이미지 + doi.json)"는 사내 드라이브로 옮기기 쉽도록 zip 한 개로 바꿨다(안 풀어도 되고 한 파일이라 빠뜨릴 일이 없다).
- **형식 v1**: `manifest.json`(`format="mi-planner-doi-package"`, `format_version`, `package_id`, 보낸 곳·메모, DOI 레코드 + 이미지별 `uid`·`path`·`sha256`·`size`·캡션·순서, 선택적 미리보기 `thumb_path`·`thumb_sha256`) + `README.txt` + `images/<DOI uid>/<이미지 uid>.<ext>`(+`.thumb.jpg`). 사람·LLM이 메모장으로 읽을 수 있게 들여쓴 JSON. 더 높은 `format_version`은 "앱을 업데이트하라"는 안내와 함께 거부한다.
- **내보내기**: 초안·휴지통 DOI는 제외(개수를 알려 줌). 이미지 파일이 없으면 조용히 빼지 않고 어떤 DOI 때문인지 알리며 실패한다. 회사 데이터 반출(D-17)은 사용자가 파일을 직접 옮기는 일이므로 앱은 파일만 만든다. 보내는 곳 이름은 입력한 값만 쓴다(PC 사용자 이름 등을 자동으로 넣지 않는다).
- **검증(가져오기 1단계, 저장 없음)**: zip-slip(`..`·절대·드라이브·역슬래시·빈 칸 이름), 심볼릭 링크, 암호 걸린 항목, 같은 이름 중복, 압축 해제 800MB·파일 12,000개·패키지 300MB·DOI 2,000개·이미지 25MB 한도를 모두 거부한다. 매니페스트의 경로는 `images/<DOI uid>/<이미지 uid>.<ext>`(uid는 hex 32자)와 정확히 같을 때만 받고, **실제 저장 경로는 zip 안 이름이 아니라 검증된 uid로 새로 만든다**. 이미지는 크기·sha256·파일 머리(PNG·JPG·GIF·WEBP·BMP, SVG 거부)가 모두 맞아야 하며 하나라도 틀리면 패키지 전체를 거부한다. 검증을 통과한 파일만 `data/doi/.package/<token>/`에 풀고, 24시간 지나면 정리한다.
- **분류**: DOI `uid` 기준 — 새 항목 / 이미 있음(항목·태그·이미지 sha256·캡션·순서가 같음, 휴지통에 있어도 같음) / 충돌(uid는 같은데 내용이 다르거나, 이미지 uid가 다른 DOI와 겹침). 선택은 버튼 칩(D-12): 새 항목 `가져오기|건너뛰기`, 충돌 `건너뛰기|둘 다 두기|내 것 덮어쓰기`. 기본값은 새 항목만 가져오기, 충돌은 건너뛰기.
- **덮어쓰기는 내가 만든(`origin='mine'`) DOI에만** 허용한다. 이미 가져온 DOI(읽기 전용)나 이미지 uid가 겹치는 경우는 `건너뛰기|둘 다 두기`만. 덮어쓰면 그 DOI는 보낸 사람 내용의 `imported`(읽기 전용)가 되고, 이전 내용은 `data/doi/.trash/overwritten_<시각>_<uid>.json`, 이전 이미지 파일은 같은 `.trash`로 옮긴다. `둘 다 두기`는 새 DOI uid·새 이미지 uid로 따로 만든다.
- **가져온 항목**: `origin='imported'`, `status='ready'`, `package_id`=패키지 ID, `source_ref`="공유 패키지 · 보낸 곳 · 날짜 가져옴"(상세 패널 `가져온 곳`), 원래 부서·작성자(`source_dept`·`source_author`)는 그대로. D-33대로 수정·이미지 변경은 409.
- **원자적 적용**: 새 파일을 `*.part`로 먼저 복사(sha256 재확인) → DB는 한 트랜잭션 → 교체되는 옛 파일을 `.trash`로 옮기고 `*.part`를 제 이름으로 바꾼 뒤 commit. 어느 단계든 실패하면 rollback + 옮긴 파일·새 파일을 되돌려 라이브러리는 그대로다(스테이징은 남겨 다시 시도 가능).
- 가져온 DOI의 새 버전을 받는 "갱신" 선택은 두지 않았다(읽기 전용 원칙). 필요하면 사용해 본 뒤 결정(WORKLOG "다음에 할 것").

### D-34 DOI PPT 가져오기도 표준 라이브러리로 읽는다 (P5-03, 2026-11-24)
`.pptx`는 `zipfile` + `ElementTree`로 읽는 `app/pptx_read.py`로 구현한다. **python-pptx(와 Pillow, lxml)를 추가하지 않는다**(D-31·D-32와 같은 이유: 보안망 오프라인 설치 부담). 새 의존성 없음, 마이그레이션 없음.
- **읽는 것**: 슬라이드 순서(presentation.xml), 제목(제목 자리표시자, 없으면 첫 짧은 줄), 본문(텍스트 상자·표·그룹 도형 안), 발표자 노트, 삽입된 그림(`ppt/media`, 도형 채우기 그림 포함). 슬라이드 번호·날짜·바닥글 자리표시자는 버린다. 숨긴 슬라이드는 표시만 하고 기본 선택에서 뺀다.
- **가져올 수 없는 것**: EMF·WMF·TIFF·SVG·알 수 없는 형식은 건너뛰고 이유를 슬라이드별로 보여 준다(DOI 이미지 형식은 D-33과 같음). 파일 밖 링크 그림, 장당 25MB·DOI당 40장 초과도 이유와 함께 건너뜀. 잘린(crop) 그림은 원본 전체를 가져오고 표시한다.
- **한도**: 파일 300MB, 슬라이드 500장(넘으면 앞부분만 읽고 안내), 이미지 총량 1GB, 압축 해제 예상 크기 상한. DTD/엔티티 거부. `.ppt`·암호 걸린 파일·ZIP이 아닌 파일은 한국어 안내.
- **흐름**: `POST /api/doi-import/pptx`(원문 바이트)가 그림을 `data/doi/.import/<token>/<sha256 앞 20자>.<ext>`에 두고(메모리에 쌓지 않음, 하루 지나면 정리) 미리보기를 돌려준다 → 사용자가 고르고 고침 → `POST /api/doi-import/{token}/confirm`이 슬라이드마다 `repo.create(status='draft', source_ref='<파일>#슬라이드 N')` + `add_image`로 만든다. 확인 전에는 DB·`data/doi/<uid>/`에 아무것도 쓰지 않는다. 한 슬라이드가 실패하면 그 DOI는 휴지통으로 보내고(반쪽 초안을 남기지 않음) 나머지는 계속한다.
- **중복**: 같은 `sha256` 이미지가 이미 라이브러리(휴지통 포함)에 있으면 `이미 있음`, 같은 `source_ref`가 있으면 `이미 가져온 슬라이드`로 표시하고 기본 선택에서 뺀다(사용자가 켤 수 있음). 슬라이드의 절반 이상(3장 이상)에 반복되는 같은 그림(로고 등)은 `반복`으로 기본 제외.
- **초안 확정**: 초안은 `status='draft'`로 `초안` 표시가 붙고, 상세 패널의 `초안 확정`(또는 `초안만 보기`의 `보이는 초안 N개 모두 확정`)이 `ready`로 바꾼다. 썸네일은 만든 뒤 브라우저가 저장된 파일에서 그려 올린다(D-33).

### D-33 DOI 이미지 저장·삭제·썸네일 방식 (P5-02, 2026-11-24)
DOI 레코드는 DB(`doi`, `doi_images`), 이미지 파일은 `data/doi/<DOI uid>/<이미지 uid>.<확장자>`에 둔다(DB에는 상대 경로만, git 제외). 새 패키지 없음.
- **안정 ID**: `doi.uid`·`doi_images.uid`(uuid hex)가 PPT 가져오기(P5-03)·공유 패키지(P5-04)에서 기계 간에 유지되는 ID다. 패키지의 이미지 상대 경로도 같은 `<doi uid>/<image uid>.<ext>`를 쓰면 가져온 뒤에도 충돌이 없다. `sha256`으로 같은 파일 중복을 알아본다.
- **삭제는 휴지통**: DOI는 `deleted_at`만 채워 숨기고(되돌리기 가능), 이미지를 빼면 파일은 `data/doi/.trash/`로 옮긴다. 영구 삭제 기능은 만들지 않았다(필요하면 나중에 확인 창과 함께).
- **썸네일은 브라우저 캔버스**: 올릴 때 브라우저가 긴 변 480px JPEG를 그려 `PUT /api/doi-images/{id}/thumb`로 보낸다. 서버에 Pillow 등 이미지 라이브러리를 두지 않는다. 썸네일이 없으면 원본으로 대신한다.
- **이미지 검증**: 확장자가 아니라 파일 앞부분(PNG·JPG·GIF·WEBP·BMP)으로 판별한다. SVG는 스크립트를 담을 수 있어 받지 않는다. 장당 25MB, DOI당 40장.
- **가져온 DOI(`origin='imported'`)는 읽기 전용**: 수정·이미지 변경은 409. 휴지통 이동·되돌리기만 허용한다. `status='draft'`는 PPT 가져오기 초안 표시용이다.
- Plan/Step 연결은 이름 문자열(`product`+`plan`)로 하고, 같은 이름의 Plan이 있으면 상세에서 `#/plans/<id>`로 이어 준다. Plan을 다시 가져오거나 지워도 DOI가 깨지지 않는다.

### D-32 Plan/Step 엑셀 가져오기도 표준 라이브러리로 읽는다 (P5-01, 2026-11-24)
`.xlsx` 가져오기는 `zipfile` + `ElementTree`로 읽는 `app/xlsx_read.py`로 구현한다(공유 문자열·인라인 문자열·숫자·날짜 서식·숨김 시트/행 지원, 수식은 저장된 값). **openpyxl을 추가하지 않는다**(새 의존성 없음, D-31과 같은 이유). 업로드는 `python-multipart` 없이 원문 바이트 본문으로 받는다. 구형 `.xls`는 지원하지 않고 .xlsx로 저장해 달라고 안내한다.
- 키: Plan = (제품, Plan 이름), Step = Plan 안에서 Step ID(없으면 이름). 다시 가져오면 이 키로 갱신하고 새 파일에 없는 Step은 지우지 않고 `파일에 없음`으로 표시한다(되살아나면 해제).
- 미리보기(dry run) → 확인 순서는 같은 API(`dry_run`)로 처리한다. 열 지정은 머리글 이름으로 `settings.plan_mapping`에 저장한다.
- 지정하지 않은 열은 버리지 않고 `extra`(JSON)로 보존해 표에 보여 준다(실제 열 구성을 아직 모르므로).

### D-31 엑셀 내보내기는 표준 라이브러리로 직접 쓴다 (P4-07, 2026-11-24)
평가 현황판 .xlsx는 `zipfile` + XML로 쓰는 `app/xlsx.py`로 만든다(문자열은 inline, 머리글 스타일·열 너비·머리글 고정·자동 필터만 지원). 새 패키지를 추가하지 않는다.
- 이유: 보안망 오프라인 설치 부담을 늘리지 않고, 내보내기는 쓰기 전용이라 openpyxl이 필요 없다. 테스트는 zipfile·ElementTree로 다시 읽어 구조(모든 파트가 XML로 파싱되고 시트·셀이 맞음)를 확인한다.
- openpyxl은 P5-01의 **가져오기**에서만 필요하면 그때 따로 결정·기록한다. 실제 Excel에서 열리는지는 회사 PC 확인 항목(project_flow VERIFY).
