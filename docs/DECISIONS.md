# DECISIONS — 결정 기록

> 상태: `확정` / `잠정`(확인 필요) / `폐기`. 바꿀 때는 지우지 말고 상태와 이유를 갱신한다.

## 결정

### D-01 기술 스택 — 확정 (2026-11-24)
Python 3.11+ / FastAPI / uvicorn / sqlite3 + 빌드 없는 vanilla JS, 표는 Tabulator. (캘린더 FullCalendar는 v0.2에서 제외 — 월간 일지 그리드가 대신함)
- 이유: 회사 PC에서 Node 빌드 체인 없이 돌아가고, 사용자가 Python을 이미 씀. FastAPI는 AI 모델들이 안정적으로 다루는 스택.
- 2026-11-24: 회사 PC에 Python 있음, pip은 사내 프록시 경유로 대부분 가능 → `install.bat`이 프록시 설정을 받아 설치. 막힌 패키지만 wheel로.
- 추가 예정 패키지(모두 순수 Python 또는 공식 wheel 제공): openpyxl(엑셀 가져오기·내보내기), python-pptx(DOI PPT 가져오기).
- 노트 편집기 라이브러리는 P3-01에서 결정 (빌드 없이 vendor 가능한 것만).

### D-02 앱 형태: 로컬 웹앱 — 확정
로컬 서버(127.0.0.1) + 브라우저 UI. Electron/Tauri는 쓰지 않는다.

### D-03 저장소: 파일(vault) + SQLite — 확정 (2026-11-24 변경)
- **노트·일지·HTML 페이지 → `vault/` 폴더의 일반 파일** (.md / .html)
- **할일·평가·MOS·레시피 같은 정형 데이터 → `data/mi_planner.db`**
- 이유: 사내 LLM 에이전트가 앱 없이도 노트를 파일처럼 바로 읽고 쓸 수 있고, 연도별로 폴더째 떼어 보관하기 쉽다(원노트 "파일 분리" 대체). 정형 데이터는 정렬·집계가 필요해 DB.
- 이전: "SQLite 단일 파일"(v0.1) → 폐기.

### D-04 오프라인 우선 — 확정
CDN 금지, 프론트 라이브러리는 `web/vendor/`, Python 패키지는 회사 이식 시 `vendor/wheels/`.

### D-05 에이전트 규칙 단일 원천 — 확정
규칙은 `AGENTS.md`에만. `CLAUDE.md`는 `@AGENTS.md`로 불러온다.

### D-06 진행 관리: project_flow.html — 확정
`FLOW` 데이터가 원본, 에이전트가 `done: true`로 갱신. 2026-11-24 단계 재편으로 브라우저 저장 키를 `mi_planner_flow_v2`로 바꿈(옛 체크와 섞이지 않게).

### D-07 모델 역할 분담 — 확정
설계·큰 판단은 Opus(채팅), 구현은 Claude Code Sonnet, 디버깅·테스트·반복은 Codex.

### D-08 페이지 = 폴더 (folder-note) — 확정
페이지 하나 = 폴더 하나(`_page.json` + `index.md` 또는 `index.html`). 하위 페이지 = 하위 폴더.
- 이유: 컨플루언스식 계층. 옵시디언에서 "폴더 자체에 노트를 못 단다"는 불만을 구조적으로 없앤다.
- 페이지 종류: `note` / `html` / `journal` / `board` / `table`.

### D-09 대기 관리 = 평가 단계 이력 — 확정
v0.1의 `queue_items`(검사·Review 대기 별도 관리)를 폐기. 평가 현황판 칸의 **단계 전환 이력**(`eval_stage_log`)으로 대기 시간을 계산한다.
- 단계는 평가마다 편집 가능. 마스터: 검사대기 → 검사완료 → 리뷰대기 → 리뷰완료&분류대기 → 분류완료 → 정리완료.
- 칸에는 단계 외에 값 항목(숫자·텍스트·OK/NG·체크)도 입력.

### D-10 LLM 연동 2단계 — 확정
1단계: 파일 + `skills/` + 에이전트용 CLI + "AI에게 요청" 복사 버튼 (사내 OpenCode / Claude Code / Codex 공통).
2단계: 사내 LLM API 직접 호출(앱 내 채팅). Python 호출 가능 확인(2026-11-24), 인증은 사내 프록시가 처리. 주소·키·모델은 `config/local.json`(git 제외), 호출은 `app/llm.py` 한 곳.
- 논문·특허 작성, PPT, 강의 HTML 같은 **생성 작업은 앱 기능이 아니라 스킬**로 만든다. 앱을 작게 유지.

### D-11 RCP 관리: 읽기 전용 우선 — 확정
수집·파싱·비교·이력까지 먼저. 수정·업로드는 P6 마지막에 **자동 백업 + diff 미리보기 + 명시적 확인 + 로그**를 갖춘 뒤, 설정에서 켤 때만.

### D-12 UI: 드롭다운 대신 버튼 — 확정
필터·보기 전환·상태 변경은 토글 칩/버튼으로. 선택지가 10개를 넘을 때만 검색 가능한 목록.

### D-13 일지 자동 표시는 옵션 — 확정
납기 할일·밀린 평가 단계를 일지 칸에 읽기 전용으로 표시. 설정에서 끄고 켬. 파일에는 쓰지 않는다.

### D-14 노트 배치: 단(column) 구조 — 확정
원노트식 완전 자유 배치 대신 컨플루언스식 단 추가 + 열 너비 조절 + 스크롤/맞춤 모드. 수평 배치는 되지만 정리는 유지.

### D-15 서식: 원노트 수준 텍스트 서식 — 확정
글자 크기·굵게·기울임·밑줄·취소선·형광펜·글자색을 위지윅 편집기로. 저장은 마크다운 + 허용 목록 인라인 HTML(`<u>`, `<mark>`, `<span style=color/font-size>`), 크기·색은 프리셋.
- 이유: 원노트의 가장 좋았던 점 중 하나. 허용 목록·프리셋으로 제한해야 파일이 깨끗하고 LLM이 읽기 쉽다.
- P3-01에서 왕복(편집→저장→열기) 보존 검증. 실패 시 note 본문을 정제된 HTML로 저장하는 쪽으로 변경.

### D-16 대상 브라우저: Chromium 계열 — 확정
Edge(회사 메인), Chrome, 네이버 웨일. Firefox·Safari는 고려하지 않는다 → 최신 CSS/JS 기능을 폴리필 없이 사용.

### D-17 사외 반출 금지 — 확정
회사 데이터는 집으로 가져오지 않는다. 집 = 가짜 데이터로 기능 개발, 회사 = 실제 데이터·회사 전용 스킬(PPT 템플릿, 레시피 파서, dcoll)·원노트 이관. 코드만 회사로 옮긴다.

### D-18 DOI = 이미지 중심 라이브러리 + 공유 패키지 — 확정
DOI는 표가 아니라 이미지 카드 + 표 겸용. 기존 PPT에서 가져오기 지원. 다른 사람·부서와는 폴더 패키지(이미지 + doi.json)를 사내 드라이브로 주고받는다. 가져온 항목은 출처 표시·읽기 전용.

### D-19 레시피 파싱: 범용 파서 + 설비사 매핑 파일 — 확정
XML/INI/TXT 범용 파서를 내장하고, 설비사별 차이는 `parsers/<vendor>.json` 매핑으로 흡수. 코드 파서는 범용으로 안 될 때만.

### D-20 노트 편집기: 직접 만든 contenteditable 편집기 (외부 라이브러리 없음) — 확정 (P3-01, 2026-11-24)
브라우저 기본 위지윅(`contenteditable`)에 마크다운 변환기(`web/js/mdconv.js`)를 직접 붙인다. Tiptap·Quill 등 후보는 쓰지 않는다.
- 이유: 빌드 도구 없이 vendor 해야 하고(보안망·외부 다운로드 불가), 저장 형식이 D-15의 "마크다운 + 허용 목록 HTML"이라 라이브러리 내부 모델이 오히려 변환 부담. 변환기를 직접 가지면 허용 목록·프리셋 제거 규칙을 한곳에서 통제한다.
- 검증(D-15 왕복): `web/test/mdconv.html`에서 제목·굵게·기울임·취소선·코드·밑줄·형광펜·색/크기·목록·체크리스트·이미지·이스케이프가 편집→저장→열기→저장에서 변하지 않음(11/11 PASS). 허용 밖 태그·스타일·프리셋 밖 값은 저장 때 제거, 읽을 때 원시 HTML은 텍스트로만 표시.
- 한계(알고 감수): 중첩 목록은 평탄화, 링크는 일반 텍스트, 붙여넣기는 서식 없는 텍스트만, 문단 사이 빈 줄은 저장 시 1개로 정리. 에디터가 `execCommand`(비권장이나 Chromium 지원 유지, D-16)에 의존 — 사라지면 이 모듈만 교체.
- 이 결정은 Opus 작업이었으나 Sonnet 세션에서 진행함. 검토 후 바꿀 점이 있으면 알려 주세요.
- 표·단(columns)은 이 편집기 위에 P3-03/P3-06에서 블록으로 추가.
