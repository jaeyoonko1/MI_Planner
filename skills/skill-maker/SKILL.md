# skill-maker — 대화로 새 스킬 만들기

먼저 `skills/README.md`(형식·공통 규칙)를 읽는다. 한 번에 질문은 1~2개만 하고, 사용자가 답한 것은 다시 묻지 않는다.

## 언제 쓰나
- 같은 종류의 요청을 반복하게 될 때(설비별 절차, 문서 형식, 표 채우기 등).
- 이미 있는 스킬로 되는 일이면 새로 만들지 말고 그 스킬을 안내한다(`skills/` 목록 확인).

## 절차
1. **목적 파악** — 아래를 대화로 채운다. 모르는 칸은 가정하지 말고 묻는다.
   - 사용자가 실제로 할 말 예시 2~3개(→ description의 재료)
   - 입력(파일 경로, 표, 평가 ID 등)과 원하는 산출물(파일 형식·위치)
   - 사람이 꼭 확인해야 하는 지점, 절대 하면 안 되는 것
2. **이름 정하기** — 소문자·숫자·하이픈, 40자 이하, 동작이 드러나게(`fill-table`). `skills/<이름>/`이 이미 있으면 덮어쓰지 말고 사용자에게 묻는다.
3. **초안 작성** — `skills/<이름>/SKILL.md`를 `skills/README.md` 형식으로 쓴다.
   - description: 무엇을 하는가 + 언제 쓰는가 + 사용자가 할 법한 말. 1~2문장.
   - 본문: 입력 → 번호 절차 → 출력 → 하지 말 것. 데이터 접근은 `python -m app.cli`(AGENTS.md 9장)를 쓰고 명령을 그대로 적는다.
   - 예시는 가짜 값만(`LOT-TEST-001`, `EQ-A01`). 실제 회사 Lot·설비·레시피명 금지.
   - 반복되는 계산·변환이 있으면 `scripts/`에 표준 라이브러리 파이썬으로 둔다.
4. **검사** — `python scripts/check_skills.py` 실행. 오류가 있으면 고치고 다시 실행.
5. **시험** — 사용자가 준 예시 요청 하나로 가짜 데이터에 스킬을 따라 돌려 본다. 막히는 단계는 SKILL.md를 고친다.
6. **보고** — 만든 파일 경로, 시험 결과, 사람이 확인해야 할 것(회사 PC에서만 가능한 것)을 짧게 적는다. 커밋은 사용자가 요청할 때만 한다.

## 하지 말 것
- 외부 네트워크·CDN·외부 API를 쓰는 절차를 넣지 않는다(오프라인 규칙).
- RCP 쓰기·DB 직접 수정·`vault/` 파일 즉시 삭제를 시키는 절차를 넣지 않는다.
- 한 스킬에 목적이 둘 이상이면 나누자고 제안한다.
- 사용자 확인 없이 기존 스킬을 고치지 않는다.
