# paper-patent — 논문·특허·기술자산화 초안

도우미: `python skills/paper-patent/scripts/paper_patent.py refs|outline|check`(표준 라이브러리, 네트워크 없음).
결과는 **새 노트 페이지**(기본 위치 `vault/성과/`) 하나. 초안일 뿐이며, 최종본은 사람이(특허는 사내 IP 담당·변리사가) 검토한다.

## 언제 쓰나
| 종류 | `--kind` | 이럴 때 |
|---|---|---|
| 사내 논문(기술 발표·사내 학회) | `paper` | 결과를 이론·방법·결과·논의로 설명해야 할 때 |
| 특허(직무발명 신고·명세서 초안) | `patent` | 새 구성·방법을 권리로 남길 때(청구항 필요) |
| 기술자산화(노하우 문서) | `asset` | 재현 절차·판단 기준을 회사 자산으로 남길 때 |
- 종류가 애매하면 묻는다: "새 장치·방법을 권리화"→patent, "결과를 알리기"→paper, "다른 사람이 똑같이 하게"→asset.
- 표 값 채우기는 `fill-table`, 현황 정리는 `status-brief`, PPT는 `pptx-company`.

## 입력
- 참고 자료: vault 페이지 폴더, `.md/.txt/.html/.csv/.tsv/.json` 파일, 폴더. 'AI에게 요청'의 위치·선택 글도 자료다(선택 글은 `data/tmp/pp-src/선택.md`에 UTF-8로 저장해 쓴다).
- **링크는 열지 않는다**(오프라인 규칙). 웹·사내 포털 링크는 사용자에게 본문을 붙여넣게(또는 파일로 저장) 하고 그 파일을 쓴다. PDF·Word·PPT·한글은 본문을 복사해 `.txt`로 저장해 달라고 한다.
- 처음에 묻는 것(한 번에 1~2개, 이미 답한 것은 다시 묻지 않음): ① 종류 ② **핵심 주장 한 문장**(무엇이 기존보다 무엇이 얼마나 나은가) ③ 제목(없으면 제안) ④ 저장 위치(기본 `성과`).

## 절차
1. **자료 모으기** — `python skills/paper-patent/scripts/paper_patent.py refs "vault/연구 개발/<페이지>" data/tmp/pp-src --out data/tmp/pp-refs.json`
   - 자료마다 `R1, R2…` 번호가 붙는다. `skipped`(못 읽은 파일)·`links`(열지 않은 링크)는 사용자에게 그대로 알린다.
   - 결과의 `excerpt`만 보지 말고, 근거로 쓸 자료는 원문을 직접 연다. 데이터 파일(`data.columns`)은 필요한 통계(n·평균·σ·최소·최대)를 **파이썬으로 계산**하고 계산식을 남긴다.
2. **논리 뼈대 먼저** — 본문 전에 주장→근거 표를 사용자에게 보여 주고 확인받는다.
   ```
   | 주장 | 근거 축 | 근거(출처) | 상태 |
   | 이중 초점으로 스캔 시간 38% 단축 | 실험·데이터 | [R1] 3장 평균 40.3→25.1분 | 근거 있음 |
   | 검출 성능은 같다 | 데이터 | [R2] 디펙 수 차이 2% 이내(n=5) | n 적음 — 추가 실험 제안 |
   | 휨이 클수록 효과가 크다 | 이론 | 없음 | [확인 필요] |
   ```
   - 축 기준: **이론**(원리·가정·식, 기호 정의) · **시뮬레이션**(모델·도구·파라미터·경계조건) · **실험**(설비·시료·조건·반복 수·측정 불확도) · **데이터**(n·평균·σ·출처 파일, 비교 기준) · **시각화**(그림마다 보여줄 주장·x/y·데이터 출처) · **논리**(주장→근거, 대안 설명·반례·한계, 선행기술 대비 차이).
   - 근거가 없는 주장은 지우거나 `[확인 필요]`로 남기고, 무엇을 하면 근거가 생기는지(실험·시뮬레이션) 한 줄로 제안한다.
3. **뼈대 페이지 만들기** — 미리보기: `… paper_patent.py outline --kind patent --title "이중 초점 스캔 방법" --refs data/tmp/pp-refs.json --parent 성과`
   사용자가 좋다고 하면 같은 명령에 `--apply` → 새 페이지(`_page.json`에 `skill`, `doc_kind`)가 생긴다. 같은 이름이 있으면 `(2)`가 붙고, 기존 페이지는 건드리지 않는다. vault 경로를 바꾸려면 `--vault`를 `outline` **앞**에 쓴다.
4. **본문 쓰기** — 결과의 `file`(index.md)을 연다. `[확인 필요]` 자리를 2번 표의 근거로 채운다.
   - 숫자가 있는 문장에는 출처를 단다: `[R2]`, `(출처: data/…/scan.csv, 계산: 평균)`, `[실험 YYYY-MM-DD]`, `[시뮬 조건 표 1]`.
   - 원문을 길게 베끼지 않는다(인용은 1~2문장, 출처 표시). 자료에 없는 수치·문헌·실험은 쓰지 않는다.
   - 그림은 '그림 계획' 표로 남긴다. 그래프가 필요하면 자식 html 페이지(오프라인, 라이브러리는 `web/vendor/`)로 만들고 그 경로를 적는다.
   - **patent**: 청구항 1(독립항)은 필수 구성요소만 한 문장, 종속항은 `제N항에 있어서,`로 시작하고 앞 번호만 인용. 청구항에서 `상기 X`는 앞에서 X를 먼저 도입한 뒤에만 쓴다. 과제의 해결 수단·청구항 1·요약은 같은 말을 쓴다. 효과는 실험예 수치로 뒷받침.
   - **paper**: 초록 5문장(문제→방법→정량 결과→의의). 결과는 데이터 → 그림 → 해석 순.
   - **asset**: 재현 절차는 다른 엔지니어가 그대로 따라 할 수 있게 번호 단계로, 판단 기준은 숫자로.
5. **검사** — `… paper_patent.py check "vault/성과/<제목>/index.md"`
   - `missing_sections`(빠진 장) · `undefined_citations`(참고문헌에 없는 `[R#]`) · `unused_refs` · `placeholders`(남은 `[확인 필요]`) · `unsourced_numbers`(출처 없는 수치 문장) · `claims.issues`(번호·인용 오류) · `claims.antecedent`(앞에서 도입 안 한 `상기 X`) · `external_links`.
   - 고칠 수 있는 것은 고치고 다시 검사한다. 남은 `[확인 필요]`는 사용자가 채울 것이므로 지어내 채우지 않는다.
6. **보고** — 아래 출력 형식으로.

## 출력
```
특허 초안: vault/성과/이중 초점 스캔 방법/ (청구항 4: 독립 1 · 종속 3)
근거 있는 주장 2 / 3 — "휨이 클수록 효과" 는 근거 없음 → 휨 3수준 실험 제안
남은 확인: [확인 필요] 5곳(도면 설명, 보안 등급 …) · 출처 없는 수치 0 · 인용 오류 0
다음: 사내 IP 담당 검토 전 외부 발표·사외 메일 금지(신규성)
```

## 하지 말 것
- 링크·외부 사이트·외부 번역기·외부 LLM에 자료를 보내거나 열지 않는다(오프라인·사외 반출 금지 D-17).
- 자료에 없는 수치·실험 결과·문헌·선행특허 번호를 지어내지 않는다. 계산했으면 계산식을 남긴다.
- 기존 페이지를 덮어쓰거나 지우지 않는다(새 페이지만 만든다, 지울 것은 `vault/.trash/`로).
- DB를 직접 고치지 않는다. RCP(레시피) 쓰기 금지(D-11).
- 예시·시험에는 가짜 값(`EQ-A01`, `LOT-TEST-001`)만. 실제 회사 문서는 회사 PC에서만 다룬다.
